以下内容为本次会议中针对 App 设计提出的**修改建议**，主要用于后续方案调整与细化参考，**不作为完整的产品设计说明**。

## 1. 登录 / 注册界面调整建议

- App 初始进入时，建议先展示**登录界面**，而不是首页主界面。
- 用户可以使用游客登录进入主界面，但是进入订单/下单等用户登录需要的页面则跳转到登录页面，禁止未登录进入。游客登录时展示默认头像与名称。
- 当前版本中，登录/注册页建议保持简洁，主要保留以下内容：
  - **账号登录**（不需要手机号/邮箱切换，用户可以在第一个栏输入手机号或邮箱，第二个栏输入密码，然后后端会判断那个是手机号还是邮箱，进行登录操作）
  - 登录块的左下角放“前往注册”，右下角放“忘记密码”，不放在最上面，注册/忘记密码页这个位置也有登录页的链接
  - 注册时现在不要两种注册方式了，用户注册时必须输入手机号（不验证）、邮箱号、邮箱验证码、密码
- 页面中建议展示“爱团”两个字以及 **App Icon / Logo**（居中展示可能更好看？），增强应用识别度。不要其他的描述文字。
- 需要再设计的美观、现代优雅一些。

## 2. 底部导航栏调整建议

- App 主体结构建议采用底部导航栏，只在首页等个别页面展示，如外卖下单页不展示
- 底部导航栏建议保留 4 个一级入口：
  - **首页**
  - **消息**
  - **订单**
  - **我的**

## 3. 主界面调整建议

- 设计参考美团，参考stage2/截图/首页参考图.jpg

- 搜索栏下方不要现在的那个栏，直接删掉，下方直接接八个入口

- “上门按摩“”改为“洗脚按摩”，所有地方都改

- 分类下方的内容展示方式，建议改为**双列信息流布局**，风格可参考美团。

- 商品卡片的展示重点建议放在：

  - **图片**
  - **价格**

- 用户点击商品后，进入**商品详情页**。

  

- 在商品详情页中，除了展示商品本身的信息外，建议保留**跳转到店铺信息页**的入口，方便用户进一步查看商家内容。

## 4. 店铺信息相关建议

- 店铺信息页的设计建议进一步完善，目前可先明确：
  - 店铺相关页面建议具备**搜索能力**；
  - 用户在查看商品后，应能方便地回到对应店铺进行浏览。
- 其中，外卖模块与其他模块逻辑不同，这个我和你说过。

## 5. 搜索逻辑调整建议

- 搜索功能建议支持以下维度：
  - **商家名称**
  - **商品名称**
  - **商家自身标签**
  - ……（你能想到的其他搜索）
- 也就是说，用户输入关键词后，搜索结果应尽量覆盖以上几类信息。
- 搜索结果不管搜到的什么，都按一种规格展示：整个大框是一个商铺，包括图标和一些信息，然后套着一个小框展示搜到的一些商品（搜的不是商品，比如是店铺，这时候没有对应商品，则默认显示热门商品），这种模仿美团，参考'stage2/截图/搜索结果参考图.jpg'
- 如果没有搜到任何相关内容，就显示一行字说没搜到，然后底下是一些热门推荐，推荐的展示框和上面搜索结果的框样式一样。

## 6. 外卖界面调整建议

- 进入外卖页面后，建议：
  - **不显示底部导航栏**
  - 左上角提供**退出 / 返回按钮**
- 外卖结算部分建议采用**底部上拉面板**的交互形式（现在做成了一个单独的页面），方便用户在当前页面直接查看已选内容并完成结算。参考美团。

## 7. 订单模块调整建议

- 用户提交订单界面应该可以选择支付方式，然后点提交订单直接跳到对应支付，如果返回到应用则要展示当前订单页-未支付
- 订单页建议按订单状态进行区分，当前可先分为以下几类：
  - **未支付（用户进来还可以支付）**
  - **待完成（外卖又有多种其他状态）**
  - **已使用**
- 当订单处于**已使用**状态后，建议开放**评价功能**。
- 用户完成订单后，应可进入具体订单详情，并基于该订单对对应店铺进行评价。

## 8. 会后确认结论

1. **商品详情页加入当前首包**：用户从首页商品卡、搜索结果命中商品、非外卖店铺服务项进入商品详情页；商品详情页保留跳转店铺信息页入口。外卖商品仍以店铺点单为主，但商品详情页也可作为展示型入口承接首页商品卡。
2. **底部导航确定为：首页 / 消息 / 订单 / 我的**。收藏不再作为一级 Tab，但在“我的”中保留收藏入口；“我的”中也必须保留订单入口和消息入口。
3. **外卖页底部上拉面板是购物车，不替代确认订单页**。购物车上拉面板展示已选商品、总价、配送费、优惠等信息，点击提交后仍进入确认订单页。
4. **支付方式保留可扩展接口**。当前前端只展示“模拟支付”，订单确认页可选择支付方式；选择模拟支付后提交订单并直接支付成功，跳转订单页展示最新状态，后续可扩展支付宝、微信等真实支付方式。

## 9. 第二轮补充确认结论

1. **外卖和其他七个模块页面与逻辑完全不同**。外卖不管点击商品还是商家，都进入外卖商家点单页；该页顶部只展示较短的商家名称、图片、简介等必要信息，下面是外卖商品选购点单，底部继续使用购物车和上拉面板逻辑。
2. **其他七个模块保留商家页和商品页两类页面**。非外卖商家页不同于外卖点单页，应展示更多商家信息，向下浏览商家商品/服务列表，不展示外卖购物车底部栏；点击商品/服务进入商品详情页，在商品页完成购买。
3. **首页八个模块入口进入模块展示页**。模块展示页结构为搜索框、热门推荐、下面可持续滑动的单列商品推荐，不直接进入普通搜索结果页。
4. **首页猜你喜欢需要支持持续下滑和动态刷新**，前端设计上按可无限加载的信息流处理。
5. **演示页面不展示无关说明文字**，例如“双列信息流”等只属于设计说明，不应出现在用户界面中。
6. **订单列表页面弱化按钮**。订单卡片整体可点击进入详情，列表中不放过大的操作按钮。
7. **非外卖商品购买后的订单流转单独设计**。非外卖支付后进入“未使用”状态，订单详情展示二维码或券码号，供商家核销；核销后进入“已使用”，再开放评价。外卖和非外卖订单详情页面需要单独设计。
8. **搜索结果页顶部分类改为系统八个分类**，不要出现“地点、笔记”等与当前系统无关的分类；筛选栏只保留地点、排序方式、筛选。
9. **演示文案必须使用爱团体系命名**。参考美团只是视觉和结构参考，页面中不要出现“美团好店”等外部平台文案。

## 10. 第三轮补充修改点

1. **首页顶部需要增加主色强化区域**。当前首页整体主色露出不足，首页最上方可以加入一段主色区域，让品牌感更明显。
2. **个人页面暂不展示“最近订单”栏目**。个人页保留常用入口、常用工具和设置等内容，最近订单先移除。
3. **首页八个入口中的“洗脚按摩”改为“洗脚”**。首页入口展示更短，但业务模块仍承接洗脚按摩相关服务。
4. **搜索结果页顶部筛选结构继续调整**。搜索框下第一行最前面加入“问小爱”入口；第二行地点筛选格要显示当前订单地点，筛选标签整体更方一些，并表现为可下拉选择。
5. **主题配色从黄色改为红色系，已确认采用肯德基红方案**。不要渐变色或炫酷颜色，统一所有文档和 HTML 原型的主题风格；主色使用 `#E4002B`，深红使用 `#B80022`，浅红底使用 `#FFF0F2`，边框红使用 `#F3B8C1`。

## 11. 第四轮真实前端化补充结论

1. **当前阶段按真实 APP 前端继续建设**，不再按演示 APP 逻辑补页面；暂时只有数据来自 Mock，交互和数据边界要服务后续后端接入。
2. **登录注册页优化找回密码状态**。进入找回密码后，辅助入口应提供“返回登录”，不再继续显示“忘记密码”。
3. **文案去除校园限定表述**。爱团是通用生活服务平台，APP 和后续文档不应出现具体高校周边等限定文案。
4. **首页猜你喜欢自动加载**。用户滑动接近列表底部时继续加载内容，不再通过点击按钮刷新。
5. **订单详情页移除演示状态切换**。订单状态来自订单数据，不允许用户在详情页手动切换状态。
6. **外卖商家页增加内容切换**。商家简介下方加入“下单 / 评价 / 商家”切换，下单区展示商品分类与商品列表，评价区展示用户反馈，商家区展示更详细信息。
7. **模块页必须按服务类型过滤**。进入某个服务模块后，只展示该模块对应的商家与商品；商家也只能展示绑定服务类型下的商品/服务。
8. **模块页精选改为商铺聚合结构**。热门推荐仍可保留商品卡布局，下面精选改为类似搜索结果的“商铺卡 + 横滑商品/服务卡”。
9. **搜索页动作按钮动态变化**。搜索框有输入内容时，右侧从“取消”变为更显眼的“搜索”；输入为空时恢复“取消”。
10. **搜索结果命中商品改为横滑卡片**。店铺卡下方的命中商品/热门商品使用图片横向卡片并支持左右滑动，不再是一条条横向长条。
11. **商家详情页增加分类侧栏**。外卖和非外卖商家展示商品/服务时，左侧加入分类栏，点击分类快速切换，对应商品按分类聚合排列。
