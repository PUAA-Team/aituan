# 爱团 APP 端页面设计（Stage 2）

## 1. 文档目标

本文档用于细化爱团用户端 APP 的前端页面设计，重点回答三个问题：

1. 每个页面**展示什么内容**。
2. 用户在页面里**可以做什么操作**。
3. 页面之间**如何跳转与串联**。

本阶段目标不是直接写 Flutter 页面代码，而是先把 APP 端的页面结构、交互逻辑和主链路定清楚，方便后续进入 UI 实现和组件拆分。

## 2. 本阶段范围

本次按会议确认后的最新范围执行：

- 登录 / 注册 / 游客进入
- 首页、八个模块展示页、搜索页、搜索结果页
- 外卖商家点单页
- 非外卖商家页、商品/服务详情页
- 外卖购物车上拉面板、确认订单、模拟支付
- 外卖订单详情、非外卖订单详情、订单列表、消息、我的、收藏、发布评价
- 当前进入真实 Flutter APP 前端建设阶段，不再维护 HTML demo；Mock 只作为临时数据源，交互逻辑按真实程序设计

> 登录方案：登录页使用一个“账号”输入框，支持手机号或邮箱 + 密码；注册页必须填写手机号、邮箱、邮箱验证码、密码。手机号要求 11 位数字，当前阶段不接短信验证码。

## 3. 设计原则

### 3.1 页面层面

1. **外卖与其他七个模块彻底分开设计**：外卖是点单和配送链路，其他七类是商品/服务购买和核销链路。
2. **一个页面只完成一个主任务**，避免一个页面承载过多无关操作。
3. **主操作固定在显眼位置**，如外卖购物车、商品详情购买按钮、订单详情状态操作区。
4. **先保证主链路顺畅**，再补 AI、会员深层玩法等增强功能。
5. **弱化学习成本**，整体操作风格贴近成熟本地生活 APP。

### 3.2 交互层面

1. 首页强调快速浏览：搜索、8 个高频入口、猜你喜欢接近底部时自动继续加载。
2. 模块展示页强调垂类浏览：搜索框、热门推荐、商铺聚合精选；进入某一模块后只展示对应服务类型。
3. 搜索结果强调店铺聚合：大框展示商铺，命中商品/服务或热门商品使用可横向滑动的小卡片。
4. 商品详情强调决策信息：图片、价格、规则、店铺入口、购买入口。
5. 外卖详情强调点单效率：短商家信息、下单/评价/商家切换、分类商品列表、购物车上拉面板、确认订单页。
6. 非外卖详情强调核销闭环：购买后进入未使用，订单详情展示二维码或券码号，核销后变为已使用。

### 3.3 视觉表达层面

1. 主色采用肯德基红风格的现代红色系，主色 `#E4002B`，深红 `#B80022`，作为主按钮、运营信息和关键引导的统一强调色。
2. 避免大面积渐变背景，整体以浅底、白卡片、细边框和局部红色强调为主。
3. 圆角体系保持克制，按钮、卡片、筛选项应有层级差异。
4. 首页和搜索结果提高信息密度，但演示页面不展示“双列信息流”等说明性文案。
5. 页面文案只使用爱团体系命名，不出现外部平台品牌文案。

### 3.4 技术落地层面

1. 页面代码继续沿用 Stage1 的 `features/*/presentation` 组织方式。
2. 大页面必须拆子组件，避免单文件过长。
3. 列表、卡片、空状态、错误态、价格组件、底部导航、吸底操作栏要复用。
4. 外卖订单详情和非外卖订单详情可以共用基础数据模型，但页面组件应分开组织。

## 4. APP 信息架构

## 4.1 底部导航

APP 主容器采用 4 个底部 Tab：

1. **首页**：发现、搜索入口、分类、猜你喜欢推荐
2. **消息**：订单通知、系统通知、互动消息
3. **订单**：用户订单列表与状态入口
4. **我的**：个人资料、订单入口、消息入口、收藏、地址、优惠券、会员、评价等

说明：收藏不再作为一级 Tab，但“我的”页保留收藏入口，商品/店铺卡片仍保留收藏操作。

## 4.2 八个业务模块

首页 8 个模块入口分别为：

1. 外卖
2. 团购
3. 酒店
4. 休闲娱乐
5. 电影演出
6. 丽人医美
7. 景点门票
8. 洗脚（业务承接洗脚按摩）

点击任意模块后进入对应模块展示页。模块展示页不是普通搜索结果页，而是垂类浏览页。

## 4.3 主链路

### 外卖链路

```text
首页 / 模块页 / 搜索结果
-> 点击外卖商品或外卖商家
-> 外卖商家点单页
-> 加入购物车
-> 购物车上拉面板
-> 确认订单页
-> 模拟支付成功
-> 外卖订单详情 / 订单列表
```

### 非外卖链路

```text
首页 / 模块页 / 搜索结果
-> 点击非外卖商品
-> 商品详情页
-> 确认订单页
-> 模拟支付成功
-> 非外卖订单详情（未使用，展示二维码/券码）
-> 商家核销
-> 已使用
-> 发布评价
```

### 非外卖商家浏览链路

```text
商品详情页 / 搜索结果
-> 非外卖商家页
-> 浏览更多商品/服务
-> 商品详情页
```

## 6. P0 页面详细设计

## 6.1 启动页 `/splash`

- APP Logo
- 品牌名称“爱团”
- 登录 / 注册入口
- 游客进入入口

## 6.2 登录注册页 `/login`

### 页面结构

1. 居中品牌区：App Icon / Logo、“爱团”两个字
2. 登录卡片：账号、密码、登录按钮
3. 登录卡片底部：左侧“前往注册”，右侧“忘记密码”
4. 注册卡片：手机号、邮箱、邮箱验证码、密码
5. 找回密码卡片：邮箱、邮箱验证码、新密码
6. 游客进入入口

### 页面操作逻辑

1. 默认显示登录卡片。
2. 点击“前往注册”切换到注册卡片。
3. 点击“忘记密码”切换到找回密码卡片。
4. 点击“游客进入”进入首页。
5. 登录/注册成功进入首页。

## 6.3 首页 `/home`

### 页面结构

1. 顶部栏：定位、搜索框、消息入口
2. 8 个业务模块入口
3. 猜你喜欢商品流，滑动接近底部自动加载更多
4. 底部 Tab：首页 / 消息 / 订单 / 我的

### 核心操作逻辑

1. 点击搜索框 -> 搜索页。
2. 点击任意模块 -> 模块展示页。
3. 点击外卖商品/商家 -> 外卖商家点单页。
4. 点击非外卖商品 -> 商品详情页。
5. 猜你喜欢向下滑动时继续加载更多推荐。

## 6.4 模块展示页 `/module/:moduleCode`

### 页面目标

承接首页八个模块入口，为单个垂类展示热门推荐和商品/服务列表。

### 页面结构

1. 顶部搜索框
2. 热门推荐区
3. 精选商铺聚合列表：商铺信息 + 横滑商品/服务卡
4. 上拉加载更多

### 八类模块差异

- 外卖模块：只展示外卖商家和外卖商品；商品或店铺点击都进入外卖商家点单页。
- 其他七个模块：只展示对应服务类型的商家和商品；商品点击进入商品详情页，商家入口进入非外卖商家页。

## 6.5 搜索页 `/search`

### 页面内容

1. 顶部搜索框
2. 历史搜索
3. 搜索排行榜
4. 发现推荐

### 操作逻辑

1. 输入关键词后回车或点击右侧“搜索” -> 搜索结果页；输入为空时右侧按钮为“取消”。
2. 点击历史搜索词 -> 搜索结果页。
3. 点击排行榜条目 -> 搜索结果页。
4. 点击发现推荐 -> 搜索结果页。

## 6.6 搜索结果页 `/search/result`

### 页面结构

1. 顶部搜索栏
2. 横向分类栏：问小爱、外卖、团购、酒店、休闲娱乐、电影演出、丽人医美、景点门票、洗脚
3. 筛选栏：当前订单地点、排序方式、筛选，筛选项更方正并带下拉暗示
4. 结果列表：商铺大卡 + 可横向滑动的命中商品/服务小卡
5. 无结果状态：提示未搜索到，并展示热门推荐

### 核心操作逻辑

1. 点击外卖商铺或外卖商品 -> 外卖商家点单页。
2. 点击非外卖商铺 -> 非外卖商家页。
3. 点击非外卖商品/服务 -> 商品详情页。
4. 如果命中的是店铺、标签或商家名称，商品小卡展示该店热门商品。

## 6.7 外卖商家点单页 `/merchant/detail/:storeId?type=takeaway`

### 页面目标

让用户在一个页面中快速完成外卖选购。

### 页面结构

1. 顶部短商家信息
   - 返回按钮
   - 店铺图片
   - 商家名称
   - 简短简介
   - 评分、月售、配送费、预计送达
2. 店内搜索
3. 下单 / 评价 / 商家切换栏
4. 商品分类侧栏和右侧全部商品列表；左侧分类点击后滚动定位到对应分类第一项
5. 评价摘要或商家详细介绍
6. 底部购物车栏
6. 购物车上拉面板

### 购物车上拉面板内容

- 已选商品列表
- 商品总价
- 配送费
- 服务费
- 优惠金额
- 预计实付
- 清空购物车
- 提交按钮

### 核心操作逻辑

1. 点击加号 -> 加入购物车。
2. 点击底部购物车 -> 展开购物车上拉面板。
3. 点击上拉面板“提交” -> 确认订单页。
4. 外卖页不显示底部主导航。
5. 外卖商品不进入普通商品详情页。

## 6.8 非外卖商家页 `/merchant/detail/:storeId?type=service`

### 页面目标

展示更完整的商家信息，并承接非外卖商品/服务浏览。

### 页面结构

1. 商家头图与基本信息
2. 营业时间、地址、电话、评分、标签、服务说明
3. 店内搜索
4. 服务分类侧栏和右侧全部服务列表；左侧分类点击后滚动定位到对应分类第一项
5. 用户评价摘要
6. 商家只展示与自身服务类型一致的商品/服务

### 核心操作逻辑

1. 点击商品/服务 -> 商品详情页。
2. 点击咨询 -> 咨询入口。
3. 页面底部不展示外卖购物车栏。

## 6.9 商品/服务详情页 `/item/detail/:itemId`

### 页面结构

1. 顶部图片区
2. 价格与标题区
3. 标签与销量信息
4. 服务规则/购买须知
5. 店铺信息入口
6. 用户评价摘要
7. 底部操作栏：收藏、进店、立即购买

### 核心操作逻辑

1. 点击店铺信息 -> 非外卖商家页。
2. 点击收藏 -> 登录后收藏商品。
3. 点击立即购买 -> 确认订单页。
4. 该页主要承接非外卖商品/服务。

## 6.10 确认订单页 `/checkout/confirm`

### 页面结构

1. 外卖收货地址 / 非外卖使用信息
2. 商品明细卡片
3. 优惠券选择卡片
4. 支付方式卡片
   - 当前只展示“模拟支付”
   - 后续可扩展微信、支付宝等真实支付方式
5. 费用明细卡片
6. 备注输入区
7. 底部吸底提交栏

### 核心操作逻辑

1. 点击地址卡 -> 地址列表页。
2. 点击优惠券 -> 优惠券选择弹层或页面。
3. 选择支付方式。
4. 点击提交订单 -> 创建订单。
5. 选择模拟支付时直接支付成功。
6. 外卖订单进入待完成；非外卖订单进入未使用。

## 6.11 订单列表页 `/orders`

### 页面结构

1. 顶部状态筛选：全部、未支付、待完成、未使用、已使用
2. 订单卡片列表

### 订单卡片原则

- 整个订单卡片可点击进入订单详情。
- 列表中不放过大的主按钮。
- 只保留小型状态标签和必要辅助操作。

### 状态说明

- **未支付**：订单已创建但未完成支付。
- **待完成**：外卖已支付但还未完成配送履约。
- **未使用**：非外卖已支付但未核销，订单详情展示二维码/券码。
- **已使用**：非外卖已核销或外卖已完成，可评价。

## 6.12 外卖订单详情页 `/order/detail/:orderId?type=takeaway`

### 页面结构

1. 外卖订单状态头部
2. 配送履约进度
3. 商家信息
4. 商品明细
5. 金额明细
6. 支付信息
7. 底部操作区

### 状态示例

- 未支付：取消订单、模拟支付
- 待完成：商家接单、备餐中、配送中、即将送达
- 已使用：订单完成，可评价

## 6.13 非外卖订单详情页 `/order/detail/:orderId?type=service`

### 页面结构

1. 非外卖订单状态头部
2. 券码/二维码核销区
3. 商家信息
4. 商品/服务明细
5. 使用规则
6. 金额明细
7. 支付信息
8. 底部操作区

### 状态示例

- 未支付：取消订单、模拟支付
- 未使用：展示二维码和券码号，等待商家核销
- 已使用：已核销，可评价

## 6.14 消息页 `/message/list`

承载订单通知、系统消息、客服互动提醒。

## 6.15 发布评价页 `/review/publish/:orderId`

1. 仅已使用订单可进入评价。
2. 一个订单只允许生成一条评价。
3. 提交成功后回到订单详情或订单列表。

## 6.16 收藏页 `/favorite`

集中查看收藏的店铺、商品和服务，作为我的页二级入口。

## 6.17 我的页 `/profile`

### 页面结构

1. 顶部用户信息卡
2. 常用入口：订单、消息、收藏、优惠券
3. 常用工具：地址管理、我的评价、客服咨询、会员中心
4. 设置与退出入口

## 7. 关键状态与约束

1. 游客可以浏览首页、模块展示页、搜索、商品详情、商家详情。
2. 下单、收藏、评价、消息、订单、我的资产等动作需要登录。
3. 外卖商品/商家点击都进入外卖商家点单页。
4. 其他七个模块有非外卖商家页和商品/服务详情页。
5. 外卖购物车上拉面板不替代确认订单页。
6. 当前只实现“模拟支付”，但接口和页面结构保留支付方式扩展能力。
7. 订单列表状态按“未支付 / 待完成 / 未使用 / 已使用”展示。
8. 首页入口展示为“洗脚”，业务承接洗脚按摩相关服务；上门类服务暂归入非外卖预约/到店服务体系，不单独作为首包独立模块。
