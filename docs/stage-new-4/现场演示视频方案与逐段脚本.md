# 现场演示视频方案与逐段脚本（4 分钟版）

> 本方案只覆盖老师要求录屏的内容：代码提交与流水线、Kubernetes 部署、代表性业务及自动化测试、HPA 扩缩容、依赖故障隔离。
> 组内分工、大模型使用、测试报告说明、性能对比等放在静态 PPT 中讲，不占这 4 分钟视频时长。

## 1. 总体安排

建议制作 4 段 MP4，合计 **3 分 55 秒**。也可以把四段合成一个视频，但分段更方便在对应 PPT 页面播放。成片只剩约 5 秒余量，四段必须严格按表剪辑。

| 3 | `03-HPA扩缩容.mp4` | 1:00 | 加压前、触发压力、Pod 增加、压力停止、Pod 回落 |
| 4 | `04-依赖故障隔离.mp4` | 1:00 | B 服务下线、C 降级、其他服务正常、B 恢复 |
| **合计** |  | **3:55** | 不超过 4 分钟 |

不录入视频的内容：

- 五人开发分工和录制分工；
- 大模型名称、用途和人工检查方式；

## 2. 视频 1：CI/CD、测试结果与 Kubernetes，70 秒

### 2.1 要证明什么

```text
线上页面显示旧文案
  → 真实前端代码改动
  → commit / push
  → 自动出现 CI run
  → 查看单元、API/集成、E2E 的通过数量
  → CI 成功后同 SHA CD
  → 查看 Kubernetes rollout、Pod Ready、HPA 和镜像 SHA
  → 重新访问线上地址看到新文案
```

### 2.2 推荐改动：纯展示标题中的一个词

在用户端首页功能入口卡片中，把可见标题：

```text
爱团服务
```

改为：

```text
生活服务
```

只需要修改一个文件中的一行：

```text
apps/user_app/lib/features/home/presentation/widgets/home_module_grid.dart
```

具体改动：

```diff
- Text('爱团服务', style: Theme.of(context).textTheme.titleMedium),
+ Text('生活服务', style: Theme.of(context).textTheme.titleMedium),
```

该文字只负责展示，不参与点击、路由、接口参数或业务判断，现有 E2E 和 Flutter 测试也没有用它定位元素，因此无需修改其他代码或测试。文件位于 `apps/user_app/**`，正常提交会触发微服务 CI。

### 2.4 Actions 中测试与部署结果的准确位置

| 要展示的证据 | Workflow → Job → Step | 画面中找什么 |
| --- | --- | --- |
| 单元测试 | `aituan-microservices-ci` → `Classified microservice unit tests` → `Run isolated Gateway and A/B/C/D unit tests` | Maven 的 `Tests run: N, Failures: 0, Errors: 0, Skipped: ...` 与 `BUILD SUCCESS` |
| API / 集成测试 | `aituan-microservices-ci` → `Classified microservice integration and API tests` → `Run controller, API, contract, migration, and boundary tests` | 各模块实际 `Tests run: N`、`Failures: 0`、`Errors: 0` 与 `BUILD SUCCESS` |
| E2E 测试 | `aituan-microservices-ci` → `MySQL 8 four-schema migration, isolation and gateway E2E` → `Run gateway-backed E2E scenarios` | Playwright 最后显示 `15 passed` |
| K8s 更新 | `aituan-microservices-deploy` → `Migrate, deploy, and verify Kubernetes` → `Wait for every workload rollout` | `deployment/... successfully rolled out` 和 StatefulSet rollout 成功 |
| Pod / HPA 明细 | 上述 deploy Run 底部 artifact `microservices-k8s-deployment-sha-...` → `resources.txt` | Pod 的 `READY/STATUS/RESTARTS` 与 HPA 的 `TARGETS/REPLICAS` |
| 镜像 SHA | 同一 artifact → `images-after.txt`，或现场执行 `kubectl` | `aituan-web` 等工作负载的 `sha-<提交 SHA>` |

Maven 会按测试类或模块输出多行 `Tests run: N`，目前不会统一显示为一个 `N passed`。录制时展示本轮日志中的真实数字，不要提前在字幕中编造总数；只把 Playwright 的稳定结论写成 `15 passed`。CD 日志中的完整资源表被重定向到 artifact，因此主画面推荐用终端实时 `kubectl get ...` 展示，artifact 留作原始证据。

### 2.5 必须保留

- 同一线上地址的旧文案和新文案；
- `git push` 成功；
- 新 CI run 的触发时间和 SHA；
- 单元、API/集成测试的真实 `Tests run` 和零失败；
- E2E 的 `15 passed`；
- CI 与 CD 的 SHA 相同；
- CD 中 rollout 成功信息；
- Pod `READY`、HPA `TARGETS` 和 `aituan-web` 镜像 `sha-...`；
- 部署后必须新开无痕窗口或清除站点数据，防止 Flutter Service Worker 缓存旧前端。

### 2.6 可以快进或跳过

- Maven、Flutter、npm 依赖下载；
- CI 中各 job 的长时间等待；
- 镜像上传和 Pod 拉取镜像；
- 每个服务逐一 rollout 的重复输出。

跳过处统一叠字：`原过程已快进，Run ID 与提交 SHA 保持不变`。

## 4. 视频 3：HPA 扩缩容全过程，60 秒

### 4.1 要证明什么

必须出现四个阶段，缺一不可：

1. 加压前：对应服务为 1 个 Pod；
2. 触发：运行真实业务压力脚本；
3. 响应：CPU 超过 50% 后 Pod 数量增加；
4. 恢复：压力结束并经过稳定窗口后，Pod 回落到 1。

HPA 是独立实验，不放进 CI/CD 视频。

### 4.2 逐秒脚本

| 时间 | 画面 | 配音 / 字幕 |
| ---: | --- | --- |
| 0:00—0:08 | `kubectl get hpa,pods`，高亮 1 个副本和 CPU 目标 50% | “加压前，五个 Java 工作负载各一个 Pod，CPU 目标为 50%。” |
| 0:08—0:15 | 执行 180 秒、40 并发 HPA 实验脚本；压力 Job 出现 | “现在从集群内经 Gateway 向 A/B/C/D 的真实业务接口持续加压。” |
| 0:15—0:32 | 6—8 倍速时间线：`TARGETS` 上升，Pod 从 1 增加并 Ready | “CPU 超过目标后，HPA 自动创建新 Pod。” |
| 0:32—0:50 | 叠字“压力结束，冷却过程 ×8”；副本逐步回到 1 | “压力结束后，经过 120 秒稳定窗口，副本自动回落，避免频繁抖动。” |
| 0:50—1:00 | `load-summary.json`、最大副本数、最终 5 个 HPA 为 1 | “脚本同时校验错误率、扩容结果和最终回落；本轮全部断言通过。” |

正式命令：

```bash
HPA_LOAD_DURATION_SECONDS=180 \
HPA_LOAD_CONCURRENCY=40 \
bash scripts/experiments/run_hpa_experiment.sh
```

从录制前检查、双终端操作、结果命令到异常恢复的完整步骤，见 `视频03-HPA扩缩容完整命令与录制流程.md`。

不要为了压缩视频修改真实实验时长；录满全过程后，把等待部分加速到 6—8 倍。不能手工 `kubectl scale` 冒充 HPA，也不能手工缩回 1。

## 5. 视频 4：依赖故障隔离与恢复，60 秒

### 5.1 要证明什么

故障对象为 B `merchant-catalog-service`。视频需要证明：

- B 真实从 1 个副本缩到 0；
- C 仍返回已保存的购物车快照和明确提示；
- 依赖实时商品数据的新增操作快速失败且没有部分写入；
- Gateway、A、C、D 的独立接口仍正常；
- B 恢复后写操作自动恢复，C 不需要重启。

### 5.2 前端状态与录制前置条件

前端闭环已经完成：购物车已接入 C 的真实接口并解析 `catalogAvailable`、`notice` 和服务端快照；故障时会显示黄色备用结果，禁用新增和结算，保留移除和清空；B 恢复后可一键重新检测。相关 Flutter 静态分析、68 项全量测试、Web/APK 构建和服务器真实故障预演均已通过。

录制前必须先把包含该更新的提交通过 CI/CD 部署到线上。终端只放在画面角落，用来证明 B Pod 确实从 1 变成 0；主画面必须是用户端。完整操作见 `视频04-依赖故障隔离-前端与SSH录制版.md`。

### 5.3 逐秒脚本

| 时间 | 画面 | 配音 / 字幕 |
| ---: | --- | --- |
| 0:00—0:10 | 用户端正常打开购物车，已有商品；角落终端显示 B 为 1 | “先在商品服务正常时建立购物车，C 同时保存商品快照。” |
| 0:10—0:20 | 角落终端执行故障脚本，B 从 1 变 0；主画面仍停留在用户端 | “现在真实停止 B 商品服务。” |
| 0:20—0:35 | 用户刷新购物车；商品、数量和金额仍在，顶部出现黄色降级提示 | “购物车没有崩溃。C 返回最近一次快照，前端明确提示商品服务暂不可用。” |
| 0:35—0:45 | 展示新增和结算置灰；打开购物车，点击“移除商品”成功 | “依赖实时库存的写操作被保护，但只操作 C 自有数据的移除功能仍可使用。” |
| 0:45—0:52 | 用户切到“评价”，内容正常加载；角落显示 A/C/D `code=0` | “单个商品服务故障没有带崩互动和交易等其他业务。” |
| 0:52—1:00 | B 恢复为 1；刷新购物车，黄色提示消失，新增按钮恢复 | “B 恢复后，C 无需重启，用户操作自动恢复正常。” |

SSH 服务器上的正式录制命令：

```bash
ssh aituan-new
cd /tmp/aituan-fault-demo
./record_catalog_fault_demo.sh
```

脚本在基线、故障和恢复三个阶段主动暂停，方便切换到前端拍摄；退出或中断时会尝试恢复 B 与 HPA。结构化 API 响应和完整自动实验结果保留为答辩追问证据，不在 60 秒主画面中逐个展开。

## 7. 剪辑原则

- 允许快速跳过：依赖下载、编译等待、镜像上传、Pod 拉取、HPA 冷却。
- 不允许跳过：触发动作、第一次状态、变化结果、最终恢复。
- 每次跳转保留相同的 SHA、订单号、实验目录或时间戳，证明前后属于同一轮。
- 所有加速处标明倍速；不要用静态截图冒充过程。
- 终端字号至少 22 px，字幕每句不超过两行。
- 不展示 Secrets、token、kubeconfig、真实地址或个人账号。
