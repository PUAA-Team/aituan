# 爱团 APP 前端 Flutter 实施计划（Stage 3）

## 1. 文档目标

本文档用于承接 Stage1 架构设计与 Stage2 APP 页面设计，明确用户端 Flutter 首包要完成的页面、代码结构、实现顺序、验证方式与打包交付要求。

当前仓库尚未存在真实 Flutter 用户端工程，因此本阶段不是只搭空壳，而是要从零创建可运行、可手测、可打包 APK 的用户端 APP 首包。

## 2. 已确认口径

1. 技术路线继续采用 Monorepo，用户端放在 `apps/user_app/`，使用 Flutter 原生组件实现。
2. 视觉主色使用肯德基红方案：主色 `#E4002B`，深红 `#B80022`，浅红底 `#FFF0F2`，边框红 `#F3B8C1`。
3. 不使用大面积渐变，不做炫酷色；整体以浅底、白卡片、细边框、局部红色强调为主。
4. Flutter 页面可以参考 HTML 原型，但不要求 1:1 复刻；实现时优先追求原生、顺滑、现代、本地生活 APP 风格。
5. 搜索页 `/search` 与搜索结果页 `/search/result` 必须分离。
6. 搜索结果统一采用“店铺卡 + 横向滑动命中商品/服务小卡”结构。
7. 搜索结果顶部第一行包含“问小爱、外卖、团购、酒店、休闲娱乐、电影演出、丽人医美、景点门票、洗脚”。
8. 搜索结果第二行筛选只保留“当前订单地点、排序方式、筛选”，标签更方正并带下拉暗示；搜索页输入非空时右侧按钮显示“搜索”，为空时显示“取消”。
9. 外卖与其他七个模块页面和业务逻辑分开。
10. 外卖商品或外卖商家点击后都进入外卖商家点单页，不进入普通商品详情页。
11. 非外卖商家进入非外卖商家页，非外卖商品/服务进入商品/服务详情页。
12. 外卖购物车上拉面板不替代确认订单页，提交后仍进入 `/checkout/confirm`。
13. 当前只实现“模拟支付”，但支付方式结构保留后续扩展空间。
14. 非外卖订单支付后进入“未使用”，订单详情展示二维码/券码号，等待商家核销。
15. 订单列表弱化按钮，整张订单卡片可点击进入订单详情。
16. 我的页暂不展示“最近订单”栏目，但保留订单、消息、收藏等入口。
17. 首页入口展示“洗脚”，业务承接洗脚按摩相关服务。
18. 当前阶段做真实 Flutter 前端，不再追加 HTML demo；Mock 只是临时数据源，页面逻辑按真实 APP 和后端接入边界设计。
19. 模块页、商家页必须按服务类型过滤数据；一个商家只展示自身绑定服务类型下的商品/服务。
20. 订单详情页状态来自订单数据，不保留演示用手动切换状态控件。

## 3. 首包页面范围

首包按 Stage2 已验证 HTML 原型范围实现以下页面和主链路：

| 序号 | 路由/页面 | 实现重点 |
| --- | --- | --- |
| 1 | `/splash` 启动页 | 品牌露出、登录/游客入口 |
| 2 | `/login` 登录注册页 | 手机号/邮箱登录、注册、找回密码、游客进入 |
| 3 | `/main` 主容器 | 首页 / 消息 / 订单 / 我的四 Tab |
| 4 | `/home` 首页 | 红色品牌头部、搜索、八模块、猜你喜欢接近底部自动加载 |
| 5 | `/module/:moduleCode` 模块展示页 | 模块搜索框、热门推荐、按类型过滤的商铺聚合精选 |
| 6 | `/search` 搜索页 | 搜索输入、动态搜索/取消按钮、历史搜索、排行榜、发现推荐 |
| 7 | `/search/result` 搜索结果页 | 问小爱入口、八分类、地点/排序/筛选、店铺卡 + 横滑商品卡 |
| 8 | 外卖商家点单页 | 短商家信息、下单/评价/商家切换、分类点单、购物车上拉面板 |
| 9 | 非外卖商家页 | 完整商家信息、分类服务列表、评价摘要、无购物车底栏 |
| 10 | `/item/detail/:itemId` 商品/服务详情页 | 非外卖商品决策、规则、店铺入口、立即购买 |
| 11 | `/checkout/confirm` 确认订单页 | 外卖/非外卖字段切换、模拟支付 |
| 12 | `/orders` 订单列表页 | 未支付 / 待完成 / 未使用 / 已使用聚合列表 |
| 13 | 外卖订单详情页 | 根据订单数据展示配送履约状态、商品明细、金额、操作区 |
| 14 | 非外卖订单详情页 | 根据订单数据展示二维码/券码核销区、使用规则、状态操作 |
| 15 | `/message/list` 消息页 | 订单通知、系统通知、互动提醒 |
| 16 | `/favorite` 收藏页 | 收藏商家、商品、服务展示 |
| 17 | `/profile` 我的页 | 用户资料、订单/消息/收藏/优惠券入口、工具入口 |
| 18 | `/review/publish/:orderId` 发布评价页 | 已使用订单评价，一个订单一条评价 |

以下页面首包只保留入口或路由规划，不展开完整实现：配送跟踪页、券码详情页、预约详情页、AI 助手页、真实支付页、地址编辑、优惠券详情、会员深层页面、商家端核销功能。

## 5. 实施步骤

### 5.1 创建 Flutter 工程

1. 在 `apps/user_app/` 创建真实 Flutter Android 工程。
2. 保留 Flutter 原生构建目录，删除默认计数器示例代码。
3. 建立 `bootstrap / app / core / shared / features` 结构。
4. 先使用本地 Mock 数据完成首包页面，不等待后端联调。

### 5.2 搭建全局壳与设计系统

1. 配置红色主题、字体层级、卡片圆角、按钮样式、输入框样式。
2. 实现主容器与四个底部 Tab：首页、消息、订单、我的。
3. 实现通用组件：页面脚手架、品牌卡片、价格文本、标签、商品缩略图、吸底操作栏、空态。
4. 实现路由常量、路由参数、登录拦截和游客浏览规则。

### 5.3 实现认证与启动链路

1. `/splash` 展示品牌与入口。
2. `/login` 支持登录、注册、找回密码三种状态切换。
3. 登录账号支持手机号或邮箱，手机号必须 11 位数字，邮箱校验基本格式。
4. 游客可进入首页，但下单、收藏、评价、订单、消息、个人资产等动作需登录。

### 5.4 实现发现与搜索链路

1. `/home` 实现红色品牌头部、八模块入口、猜你喜欢接近底部自动加载。
2. `/module/:moduleCode` 实现模块展示页，按模块类型过滤商家和商品，精选区采用商铺聚合 + 横滑商品卡。
3. `/search` 实现历史搜索、排行榜、发现推荐，并根据输入内容切换“搜索/取消”按钮。
4. `/search/result` 实现店铺聚合结果卡，命中商品以横滑卡片展示；外卖结果进入外卖点单页，非外卖商品进入商品详情页。

### 5.5 实现商家与商品链路

1. 外卖商家点单页：短商家头、下单/评价/商家切换、左侧分类、右侧全部商品分组列表、分类锚点滚动、加购、购物车上拉面板。
2. 非外卖商家页：完整商家信息、左侧分类、右侧全部同类型服务分组列表、分类锚点滚动、规则摘要、评价摘要。
3. 商品/服务详情页：图片、价格、标签、购买规则、店铺入口、立即购买。

### 5.6 实现交易闭环

1. `/checkout/confirm` 根据订单类型显示外卖地址/配送费或非外卖使用规则/券码说明。
2. 模拟支付后外卖进入待完成，非外卖进入未使用。
3. `/orders` 订单列表按四类状态筛选，整卡可点击。
4. 外卖订单详情与非外卖订单详情分开组件实现。
5. 非外卖订单详情展示二维码占位和券码号。

### 5.7 实现消息、收藏、我的、评价

1. 消息页展示订单通知、系统通知、互动提醒。
2. 收藏页展示收藏商家、商品、服务。
3. 我的页展示资料摘要、订单/消息/收藏/优惠券入口、工具入口，不展示最近订单栏目。
4. 发布评价页支持评分、文字输入、提交后回到订单链路。

### 5.8 补齐脚本与打包文档

1. `scripts/dev/start_user_app.ps1`：本地启动用户端 APP。
2. `scripts/build/build_android_apk.ps1`：同步源码到 D 盘英文路径并打包 debug APK。
3. `scripts/release/clean_build_artifacts.ps1`：清理本次打包冗余构建目录。
4. `docs/stage3/APP打包说明.md`：记录打包路径、命令、产物位置和清理方式。

- `flutter test`

- `/search`
- `/search/result`

- 非外卖商家页
- `/item/detail/:itemId`
- `/checkout/confirm`
- `/orders`
- 外卖订单详情
- 非外卖订单详情
- `/message/list`
- `/favorite`
- `/profile`
- `/review/publish/:orderId`

### 6.3 主链路手测

1. Splash -> 游客进入 -> 首页 -> 搜索 -> 搜索结果 -> 外卖商家点单 -> 购物车 -> 确认订单。
2. 登录 -> 首页 -> 模块展示页 -> 非外卖商品详情 -> 确认订单 -> 非外卖订单详情。
3. 登录 -> 订单列表 -> 外卖订单详情 / 非外卖订单详情 -> 发布评价。
4. 登录 -> 我的 -> 消息 / 收藏 / 订单入口。

### 6.4 打包交付

1. 构建时同步源码到 `D:/aituan_build/user_app/`。
2. 生成 APK 到 `D:/aituan_release/apk/`。
3. 交付时明确给出 APK 绝对路径。
4. 完成后清理本次打包产生的冗余构建目录，只保留最终 APK 和必要说明。
