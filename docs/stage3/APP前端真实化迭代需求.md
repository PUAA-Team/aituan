# APP 前端真实化迭代需求记录

## 1. 背景

当前 Flutter 用户端已经完成首轮静态预览和 UI 全面优化，界面风格已经接近正式产品。下一阶段不再按“演示 APP”补页面，而是以真实本地生活服务 APP 的前端逻辑继续搭建：后端暂不接入，页面数据仍使用 Mock，但交互、信息架构和数据边界要按真实程序预留。

## 2. 本次确认的需求

1. 登录注册页中进入“忘记密码”后，底部辅助入口不应继续显示“忘记密码”，应提供直达登录的入口。
2. 项目是通用生活服务平台，文案不得出现具体高校周边等校园限定表述。
3. 首页“猜你喜欢”应支持下滑自动加载，不再依赖用户点击刷新按钮。
4. 订单详情页不应保留演示用的手动切换订单状态控件，状态应来自订单数据。
5. 外卖点单页面需要加入评价栏和商家详细介绍，可在商家简介下方使用“下单 / 评价 / 商家”切换。
6. 八个服务模块必须按服务类型过滤内容；某一服务模块内只能看到对应服务。模块页热门推荐保留商品卡布局，下面精选列表改为类似搜索结果的“商铺套商品”结构。
7. 搜索页输入框内有内容时，右侧“取消”应变为更显眼的“搜索”；输入为空时恢复“取消”。
8. 搜索结果页中店铺下方命中的商品/服务不再是一条条横向长条，而应改为图片+信息的小卡片，并支持横向滑动查看。
9. 非外卖商家详情页中，一个商家只能展示与其绑定服务类型一致的服务，不能混入其他品类。
10. 外卖和非外卖商家详情页展示商品/服务时，左侧应加入商品分类栏；点击分类可以快速切到对应分类，商品按分类聚合排列。

## 3. 真实 APP 实现原则

- 现在做的是正式前端框架，不是临时演示页；只有数据是演示用 Mock 数据。
- Mock 数据结构要尽量贴近后端未来返回形态，方便后续替换为接口数据。
- UI 交互不应依赖演示按钮或人为切状态，应尽量使用真实用户路径：搜索、浏览、下单、支付、订单查看、评价。
- 外卖与非外卖继续保持两套业务逻辑：外卖以商家点单、购物车、配送履约为核心；非外卖以商家服务、商品详情、到店券码核销为核心。
- 商家与服务类型应建立明确绑定关系，商家页只展示自身服务范围内的数据。
- 页面和组件继续保持高内聚低耦合，单 Dart 文件尽量不超过 200 行。

## 4. 本次补充需求

1. 个别店铺需要补充更多商品/服务 Mock 数据，增强商家页、模块页和搜索结果的预览效果。
2. 商家详情页商品分类交互调整为：右侧始终展示该商家的全部商品/服务，并按分类分组；左侧点击分类时滚动定位到右侧对应分类的第一项，而不是只过滤显示单一分类。
3. 该交互仍按真实 APP 前端逻辑实现，后续后端只需返回分类和商品列表，前端按分类锚点滚动即可。

## 5. 文档和代码处理范围

本次需要更新相关设计与实施文档，但不再维护 HTML demo。代码改动完成后仍需执行格式化、静态检查、测试、D 盘 APK 打包和临时目录清理。
