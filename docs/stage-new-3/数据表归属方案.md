# 爱团微服务数据表归属方案

## 1. 目标与口径

本方案以 `database/migrations/` 中现有的 **60 张业务表**为基线，为每张表指定唯一所属服务和逻辑库。本轮只确定目标归属，不移动迁移脚本，不修改当前单体数据库。

| 服务 | 逻辑库 | 建议数据库账号 | 表数 |
| --- | --- | --- | ---: |
| 账号与用户资产服务 | `aituan_identity` | `aituan_identity_svc` | 17 |
| 商家与商品服务 | `aituan_merchant` | `aituan_merchant_svc` | 14 |
| 交易与履约服务 | `aituan_trade` | `aituan_trade_svc` | 11 |
| 互动与平台服务 | `aituan_platform` | `aituan_platform_svc` | 18 |
| **合计** | 4 个逻辑库 | 4 个独立账号 | **60** |

## 2. 账号与用户资产库 `aituan_identity`

| # | 表名 | 业务所有权 |
| ---: | --- | --- |
| 1 | `iam_account` | 三类账号与登录凭据 |
| 2 | `iam_verification_code` | 验证码发送与核验记录 |
| 3 | `iam_role` | 角色定义 |
| 4 | `iam_permission` | 权限点定义 |
| 5 | `iam_account_role` | 账号与角色关系 |
| 6 | `iam_role_permission` | 角色与权限关系 |
| 7 | `user_profile` | 用户档案和当前成长值 |
| 8 | `user_address` | 收货地址与定位 |
| 9 | `user_favorite` | 用户收藏关系 |
| 10 | `member_level` | 会员等级和权益配置 |
| 11 | `member_growth_log` | 成长值变动流水 |
| 12 | `member_weekly_coupon_rule` | 周券发放规则 |
| 13 | `member_weekly_coupon_batch` | 周券发放批次 |
| 14 | `member_weekly_coupon_issue` | 周券发放明细 |
| 15 | `coupon_template` | 优惠券模板 |
| 16 | `user_coupon` | 用户优惠券资产 |
| 17 | `support_station_message` | 用户站内消息与已读状态 |

### 跨服务引用

- `member_growth_log.order_id` 和 `user_coupon.used_order_id` 仅保留交易服务的订单 ID，不建立外键。
- `user_favorite.target_id` 是多态业务 ID，名称、封面、副标题作为用户资产快照保存。
- 其他服务不直接写 `support_station_message`，统一调用消息发布内部接口。

## 3. 商家与商品库 `aituan_merchant`

| # | 表名 | 业务所有权 |
| ---: | --- | --- |
| 1 | `merchant_profile` | 商家主体与经营人资料 |
| 2 | `merchant_store` | 门店基本资料、位置和营业状态 |
| 3 | `merchant_delivery_rule` | 门店配送费、起送价和范围 |
| 4 | `merchant_takeaway_setting` | 外卖接单模式和暂停规则 |
| 5 | `merchant_application` | 商家入驻申请 |
| 6 | `merchant_certification_material` | 商家资质材料 |
| 7 | `merchant_audit_log` | 入驻和资质审核轨迹 |
| 8 | `catalog_category` | 门店商品/服务分类 |
| 9 | `catalog_item` | 统一商品与服务主数据、库存 |
| 10 | `catalog_sku` | 商品规格、价格和库存 |
| 11 | `catalog_item_tag` | 商品标签字典 |
| 12 | `catalog_item_tag_rel` | 商品与标签关系 |
| 13 | `ops_banner_config` | 首页 Banner 和入口展示配置 |
| 14 | `member_recommend_config` | 首页/模块推荐位配置 |

### 跨服务引用

- `merchant_profile.account_id` 仅保存账号服务的 `accountId`，商家登录后的 `merchantId` 建议由 JWT 携带。
- 订单使用门店、商品和价格快照，商家修改目录不回写历史订单。
- 库存扣减/恢复由该服务内部接口执行，交易服务不直接更新 `catalog_item` 或 `catalog_sku`。

## 4. 交易与履约库 `aituan_trade`

| # | 表名 | 业务所有权 |
| ---: | --- | --- |
| 1 | `cart` | 用户按门店分组的购物车 |
| 2 | `cart_item` | 购物车商品明细 |
| 3 | `order_main` | 统一订单主体、金额和状态 |
| 4 | `order_item` | 订单商品/服务快照 |
| 5 | `order_payment_record` | 支付模拟与支付流水 |
| 6 | `order_voucher` | 非外卖电子券码与核销状态 |
| 7 | `order_booking_record` | 订单预约信息与确认状态 |
| 8 | `order_refund_record` | 退款申请、结果和补偿轨迹 |
| 9 | `order_state_log` | 订单状态流转日志 |
| 10 | `delivery_task` | 外卖配送模拟任务 |
| 11 | `delivery_track_node` | 配送时间线节点 |

### 跨服务引用与快照

- `order_main.user_id`、`store_id`、`coupon_id` 分别是用户资产服务和商家商品服务的逻辑引用，不建立跨库外键。
- 订单必须保留门店名称、收货地址、商品名称、单价、优惠金额和履约参数快照，历史展示不依赖远程服务可用性。
- 交易服务是订单状态和退款状态的唯一修改者，互动、AI 和看板只能通过内部查询接口读取。

## 5. 互动与平台库 `aituan_platform`

| # | 表名 | 业务所有权 |
| ---: | --- | --- |
| 1 | `review_record` | 用户评价主体和发布/屏蔽状态 |
| 2 | `review_reply` | 商家评价回复 |
| 3 | `review_helpful` | 评价有用投票 |
| 4 | `review_report` | 评价举报与证据 |
| 5 | `review_audit_log` | 评价治理轨迹 |
| 6 | `support_session` | 客服会话、AI/人工模式与平台介入状态 |
| 7 | `support_message` | 用户、商家、平台三方会话消息 |
| 8 | `merchant_support_auto_reply_rule` | 商家客服自动回复规则 |
| 9 | `complaint_ticket` | 用户投诉工单 |
| 10 | `complaint_log` | 投诉受理、处理、关闭日志 |
| 11 | `ai_assistant_conversation` | AI 助手会话 |
| 12 | `ai_assistant_message` | AI 消息、工具调用结果与降级回复 |
| 13 | `platform_announcement` | 平台公告 |
| 14 | `sys_config` | 平台运行配置 |
| 15 | `sys_dict` | 平台通用字典 |
| 16 | `sys_request_log` | 入口请求追踪日志 |
| 17 | `sys_audit_log` | 后台与内部操作审计日志 |
| 18 | `file_asset` | 统一文件元数据与业务绑定 |

### 跨服务引用

- `review_record`、`complaint_ticket`、`support_session` 中的用户、门店、商家和订单 ID 都是逻辑引用，建单/发布时经内部接口验证。
- 评价发布后的门店评分由商家商品服务查询评价摘要，不直接聚合 `review_record`。
- `file_asset` 仅保存文件元数据，门店、商品、评价等业务对象只保存稳定 URL 和自己的业务关系。
