# 后台与商家端界面重构设计

## 1. 重构目标

本次 Stage7 不是简单换颜色或微调间距，而是重构后台管理端和商家端的信息架构、页面骨架与交互方式，解决以下问题：

- 功能入口过多且缺少分组，使用时难以判断入口含义。
- 部分入口重复或业务价值不足，占据主导航空间。
- 页面布局不统一，列表、详情、编辑入口体验割裂。
- 某些信息能看到但难以修改，影响平台和商家日常维护。
- 响应式能力不足，小屏时侧栏和表格容易挤压。

目标结果：两个 Web 端都采用清晰的固定侧边栏布局，入口按照业务场景分组，页面结构统一，真实功能可访问、可编辑、可验证。

## 2. 统一设计原则

### 2.1 布局原则

- 桌面端使用固定左侧边栏，右侧为可滚动主内容区。
- 小屏幕下侧边栏收起，通过顶部菜单按钮打开。
- 主内容区由“页面标题区 + 工具栏/筛选区 + 内容卡片/表格 + 详情/编辑弹窗”组成。
- 列表页必须有加载态、错误态、空状态。
- 表格在窄屏下横向滚动，不能把内容挤压到不可读。

### 2.2 视觉原则

- 使用纯色背景，不使用渐变。
- 使用浅灰页面背景、白色卡片、浅边框、轻阴影。
- 品牌主色延续爱团红，用于当前选中、主按钮、关键数字。
- 圆角保持克制，不做全局大圆角。
- 字号紧凑，适合后台和商家端的数据密集场景。
- 所有可点击元素需要 hover、active 或 focus 反馈。

### 2.3 依赖原则

- 不新增 UI 框架。
- 不引入 Tailwind。
- 不新增图标库。
- 图标优先用内联 SVG 或统一 CSS 小图标组件。

## 3. 后台管理端信息架构

后台端面向平台运营和管理员，导航按治理场景分组。

### 3.1 导航分组

| 分组 | 入口 | 说明 |
| --- | --- | --- |
| 总览 | 平台总览 | 展示核心指标、待办、交易概览 |
| 交易履约 | 订单治理、预约治理、券码治理、配送任务 | 处理交易、履约、退款、核销与配送 |
| 商户与商品 | 商户门店、商品治理 | 管理商户资料、商品分类与商品状态 |
| 用户资产 | 用户管理、会员等级、优惠券模板 | 管理用户资料、会员体系与优惠券资产 |
| 内容治理 | 评价审核、投诉工单、平台客服、审计日志 | 处理用户互动、投诉、客服与操作追踪 |
| 系统 | 管理员资料、平台设置 | 维护管理员和系统配置 |

### 3.2 公告入口处理

公告运营当前不作为主导航保留。若后续仍需要公告数据，可保留页面文件和后端接口，但从主导航隐藏，避免无意义入口干扰日常运营。

### 3.3 页面结构

#### 总览页

- 顶部：核心指标卡片，例如今日订单、待处理投诉、待审核评价、活跃商户。
- 中部：待办清单，直接跳转对应治理页面。
- 底部：最近订单、最近投诉、最近审计记录。

#### 列表治理页

适用于订单、商户、用户、券码、预约、评价、投诉等页面。

- 标题区：页面名称、说明、刷新按钮。
- 筛选区：状态、关键词、业务类型或时间条件。
- 主体区：表格或卡片列表。
- 操作区：查看详情、编辑、审核、退款、禁用等真实操作。
- 详情区：使用右侧抽屉或弹窗展示完整信息。

#### 编辑页/弹窗

- 复用现有 `PanelModal`。
- 表单字段只展示真实可提交字段。
- 保存成功后刷新当前数据，并显示顶部 notice。
- 没有后端接口支持的字段不放假按钮。

## 4. 商家端信息架构

商家端面向商家日常经营，导航按工作流分组。

### 4.1 导航分组

| 分组 | 入口 | 说明 |
| --- | --- | --- |
| 经营 | 经营总览 | 展示今日订单、销售额、待处理事项 |
| 门店与商品 | 门店资料、商品/服务管理、履约设置 | 维护门店信息、商品服务、外卖配送规则 |
| 订单履约 | 订单中心、预约确认、券码核销 | 处理外卖订单、到店预约和券码核销 |
| 互动售后 | 评价管理、客服会话 | 回复评价、处理用户咨询 |

### 4.2 外卖与非外卖差异

- 外卖商家显示订单中心、商品管理、履约设置、评价、客服。
- 非外卖商家显示订单中心、商品/服务管理、预约确认、券码核销、评价、客服。
- 不适用的入口不展示，避免商家看到不能操作的功能。

### 4.3 商家端页面结构

#### 经营总览

- 顶部：门店营业状态、今日订单、今日收入、待处理订单。
- 中部：待办事项，例如待接单、待确认预约、待回复评价。
- 底部：最近订单和评价。

#### 门店资料

必须能编辑已有后端支持字段：

- 门店名称。
- 营业状态。
- 门店简介。
- 地址。
- 营业时间。
- 标签。
- 联系电话。
- 门店公告。
- 经纬度。
- 封面图片。

#### 商品/服务管理

- 列表展示商品名、分类、价格、状态、库存或服务属性。
- 提供编辑、上下架、刷新。
- 操作按钮必须对应真实 API。

#### 订单履约页

- 外卖订单突出接单、拒单、推进履约、退款。
- 服务订单突出券码、预约、退款。
- 状态筛选必须明显。

## 5. 组件与样式规范

### 5.1 应用框架

- 后台：重构 `AdminFrame.vue`。
- 商家：重构 `ConsoleFrame.vue`。
- 两端保持同样布局语言：左侧导航、顶部状态栏、主内容容器。

### 5.2 CSS Token

建议在各自 `styles.css` 中统一变量：

```css
:root {
  --brand: #d71918;
  --brand-dark: #a90f12;
  --brand-soft: #fff1f1;
  --text-main: #1f2937;
  --text-sub: #6b7280;
  --line: #e5e7eb;
  --bg-page: #f6f7f9;
  --bg-card: #ffffff;
}
```

### 5.3 图标规范

- 侧边栏每个入口配一个图标。
- 图标尺寸统一，普通状态灰色，选中状态品牌红。
- 不新增图标依赖。

## 6. 响应式规则

- `>= 1024px`：侧栏固定展示，主内容滚动。
- `768px - 1023px`：侧栏可保持窄宽或可收起，内容区保持卡片间距。
- `< 768px`：侧栏默认隐藏，顶部显示菜单按钮；表格横向滚动或转卡片。
