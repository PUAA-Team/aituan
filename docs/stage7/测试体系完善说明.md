# Stage7 测试体系完善说明

## 1. 目标

本阶段在不改动现有部署脚本、不依赖 Docker Compose、不提交任何真实密钥配置的前提下，补充后端、用户端 Flutter、商家端 Web、后台端 Web 的测试覆盖，并把新增测试纳入 GitHub Actions CI。

重点补齐：

- 后端 API / Controller 集成测试；
- Spring Security / JWT 角色边界测试；
- Flutter 用户端纯逻辑、模型解析、Repository 请求路径测试；
- Vue Web 端集中式 API 层测试；
- 成员 E 静态回归脚本 CI 门禁。

## 2. 后端测试

### 2.1 新增测试类型

后端新增 `MockMvc` API 集成测试，沿用：

```java
@SpringBootTest
@AutoConfigureMockMvc
@ActiveProfiles("test")
```

测试会走真实：

- Spring Security 配置；
- JWT 解析；
- Controller 参数校验；
- Jackson 序列化；
- `ApiResponse` 响应壳；
- `GlobalExceptionHandler`；
- H2 `MODE=MySQL` + Flyway 空库迁移 + seed 数据。

| 文件 | 覆盖内容 |

### 2.3 本地运行

Windows 本机建议使用 D 盘 Maven 缓存和 Java 17：

```powershell
$env:JAVA_HOME = "D:/tools/jdk-17.0.18+8"
$env:Path = "$env:JAVA_HOME/bin;$env:Path"
mvn -B "-Dmaven.repo.local=D:/aituan_cache/m2" "-Dbackend.build.directory=D:/aituan_cache/backend-target/aituan-backend" -f "services/backend/pom.xml" test
```

只跑新增 API 测试：

```powershell
mvn -B "-Dmaven.repo.local=D:/aituan_cache/m2" "-Dbackend.build.directory=D:/aituan_cache/backend-target/aituan-backend" -f "services/backend/pom.xml" "-Dtest=AuthApiIntegrationTest,SecurityBoundaryApiTest,CouponApiIntegrationTest,ComplaintApiIntegrationTest,CommonFileControllerTest,TradeApiIntegrationTest" test
```

## 4. Vue Web 测试

### 4.1 新增测试框架

商家端与后台端均新增：

- `vitest`；
- `happy-dom`；
- `@vue/test-utils`。

当前第一轮主要覆盖集中式 `src/api.ts`，不启动真实后端，使用 mocked `fetch`。

### 4.2 修改文件

| 文件 | 说明 |
| --- | --- |
| `apps/merchant_web/package.json` | 增加 `test`、`test:watch` 脚本和测试依赖。 |
| `apps/merchant_web/package-lock.json` | 锁定测试依赖。 |
| `apps/merchant_web/vite.config.ts` | 使用 `vitest/config` 并配置 `happy-dom`。 |
| `apps/merchant_web/src/env.d.ts` | 增加 Vite / Vitest 类型声明。 |
| `apps/merchant_web/src/api.test.ts` | 商家端 API 层测试。 |
| `apps/admin_web/package.json` | 增加 `test`、`test:watch` 脚本和测试依赖。 |
| `apps/admin_web/package-lock.json` | 锁定测试依赖。 |
| `apps/admin_web/vite.config.ts` | 使用 `vitest/config` 并配置 `happy-dom`。 |
| `apps/admin_web/src/env.d.ts` | 增加 Vite / Vitest 类型声明。 |
| `apps/admin_web/src/api.test.ts` | 后台端 API 层测试。 |

### 4.3 覆盖内容

Web API 测试覆盖：

- 登录路径、token/account 保存；
- `Authorization: Bearer ...` 注入；
- `auth:false` 不带 token；
- JSON body 自动设置 `Content-Type: application/json`；
- `FormData` 上传不手动设置 JSON content type；
- 业务失败和 HTTP 失败抛后端 message；
- 商家端 401 错误保留 `status`，用于登录过期处理；
- query 参数拼接；
- 券码、配置 key 的 `encodeURIComponent`；
- `resolveAssetUrl` 地址拼接。

### 4.4 本地运行

商家端：

```powershell
npm test --prefix "apps/merchant_web"
```

后台端：

```powershell
npm test --prefix "apps/admin_web"
```

## 5. CI 接入

`.github/workflows/ci.yml` 增加：

1. `static-regression` job：

```yaml
run: bash scripts/verify/member_e_regression_checks.sh
```

2. Web matrix 在 build 前运行：

```yaml
run: npm test --prefix ${{ matrix.app.path }}
```

后端与 Flutter 不需要新增 CI 命令，因为新增测试会被既有：

```yaml
mvn -B -f services/backend/pom.xml test
flutter test
```

自动覆盖。
