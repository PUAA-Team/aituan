# Stage7 第一部分计划

## 1. 目标

Stage7 第一部分完成用户端体验修复、会员资产闭环，以及后台端与商家端完整界面重构。

本阶段不是单纯美化后台和商家端，而是重新设计两个 Web 端的信息架构、页面骨架、导航分组与可编辑入口，让后台管理员和商家能更清晰地完成日常操作。

## 2. 用户端修复

### 2.1 订单页底部按钮

- 修复底部按钮全部堆在一侧的问题。
- 按语义固定左右区域：联系、说明等辅助动作在左侧；支付、退款、评价、查看商家等主动作在右侧。
- 删除重复的“查看商家”。
- 检查外卖订单详情、服务订单详情以及其他出现同类按钮的页面。

### 2.2 消息页顶部

- 删除顶部“我的咨询”和“投诉进度”快捷入口。
- 删除“订单状态、评价回复、客服会话、投诉进度都会在这里展示”等说明文案。
- “消息”和“全部已读”放到同一行。
- 保留消息分组、消息列表、已读和跳转逻辑。

### 2.3 用户端版本

- 用户端版本号升级为 `1.1.0+17`。
- 关于页展示 `v1.1.0`。
- 完成后重新打包 APK。

## 3. 会员成长值与等级

### 3.1 成长值规则

- 订单完成后按实付金额累计成长值，1 元 = 1 成长值；支付成功时不立即增加成长值。
- 发表一次订单评价 = 3 成长值。
- 订单完成、退款、评价均需要幂等，重复调用不得重复加扣成长值。
- 退款成功后退还该订单曾发放的消费成长值；若造成等级下降，已发出的会员券暂不回收。

### 3.2 会员等级

| 等级 | 成长值门槛 |
| --- | ---: |
| 白银会员 | 0 |
| 黄金会员 | 300 |
| 白金会员 | 1000 |
| 钻石会员 | 3000 |
| 红钻会员 | 10000 |
| 黑钻会员 | 30000 |

### 3.3 展示要求

- 会员中心展示当前等级、成长值、升级进度和成长规则。
- “我的”主页展示会员等级和成长值。
- 后端需要同步 `user_profile.member_level_name`，保证“我的”主页和会员中心显示一致。

## 4. 每周会员优惠券

### 4.1 发券方式

- 不依赖定时任务。
- 用户打开会员中心或我的优惠券页时懒刷新本周会员券。
- 同一用户同一自然周只发一次。
- 优惠券有效期为实际发放日起 7 天。

### 4.2 默认发券规则

| 等级 | 每周优惠券 |
| --- | --- |
| 白银会员 | 1 张：满 30 减 3 |
| 黄金会员 | 2 张：满 30 减 5、满 50 减 8 |
| 白金会员 | 2 张：满 50 减 10、满 80 减 15 |
| 钻石会员 | 3 张：满 50 减 12、满 100 减 20、满 150 减 30 |
| 红钻会员 | 4 张：满 50 减 15、满 100 减 25、满 150 减 35、满 200 减 50 |
| 黑钻会员 | 5 张：满 50 减 20、满 100 减 30、满 150 减 45、满 200 减 60、满 300 减 90 |

### 4.3 幂等要求

- 使用发券批次表记录用户每周是否刷新。
- 使用发券明细表记录每张券是否已发。
- 依靠唯一键保证并发请求不会重复发券。
- 发出的券写入现有 `user_coupon`，继续复用下单抵扣、支付核销、退款释放逻辑。

## 5. 后台端界面重构

详见 `docs/stage7/后台与商家端界面重构设计.md`。

后台端按平台治理场景重构：

- 总览。
- 交易履约。
- 商户与商品。
- 用户资产。
- 内容治理。
- 系统。

要求：

- 固定侧边栏。
- 页面结构统一。
- 公告类无意义入口不再占用主导航。
- 所有展示出来的编辑按钮必须有真实功能。
- 无渐变、响应式、清晰可用。

## 6. 商家端界面重构

详见 `docs/stage7/后台与商家端界面重构设计.md`。

商家端按商家日常工作流重构：

- 经营总览。
- 门店与商品。
- 订单履约。
- 互动售后。

要求：

- 外卖/非外卖入口按业务类型显示。
- 门店资料、营业时间、地址、封面、公告、联系方式等已有字段必须可编辑。
- 列表页具备筛选、刷新、空状态、错误态和详情操作。
- 无渐变、响应式、清晰可用。
