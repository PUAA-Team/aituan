## 1. 总目标

把"交易发生后的全部互动与治理闭环"补全：

- **用户**在订单完成后能写真实评价、看到商家回复，发起咨询、提交投诉。
- **商家**能回复评价、处理客服会话、看到自己的经营驾驶舱。
- **平台**能审核违规评价、受理与处理投诉、查看跨商家的运营数据、回溯所有审计日志。

不做的事（依然保持占位）：

- 不接真实 AI 大模型；客服快捷回复、评价标签建议、违规识别只做模板化/规则化降级。
- 不做积分体系、不做评价红包、不做投诉赔付资金流（只到工单状态推进）。

## 4. 迭代规划

按「依赖出现的先后」做四轮迭代，每一轮内部仍保持后端 → 用户端/商家端/后台端并行，但每一轮交付后整链路必须能跑通最小演示。

### 4.1 第一轮：数据库与后端接口骨架（约 3 天）

**目标**：让其他四位队友能拿到接口契约，开始联调。

1. 写迁移 `V009__interaction_governance_init.sql`：
   - `review_report`、`review_helpful`、`review_audit_log` 三张表
   - `support_session`、`support_message` 两张表
   - `complaint_ticket`、`complaint_log` 两张表
   - 在 `review_record` 表上加索引 `idx_review_store_status (store_id, status)` 便于商家分页
2. 后端新增模块：
   - `com.aituan.support`（客服会话）
   - `com.aituan.complaint`（投诉工单）
   - `com.aituan.statistics`（商家与后台驾驶舱）
3. 扩展 `com.aituan.interaction`：
   - `/api/app/interaction/reviews/me`（GET 列表，已有但需要补字段）
   - `/api/app/interaction/reviews/{id}/helpful`（POST）
   - `/api/app/interaction/reviews/{id}/report`（POST）
   - `/api/merchant/ops/reviews`（GET 商家分页）
   - `/api/merchant/ops/reviews/{id}/reply`（POST 商家回复）
   - `/api/admin/governance/reviews`（GET / POST 审核）
4. 扩展 `com.aituan.admin`：
   - `AdminDashboardView` 增加 `pendingReviews`、`pendingComplaints`、`openSessions` 三个字段
5. 所有新接口必须返回 `ApiResponse<T>` 或 `ApiResponse<PageResponse<T>>`，沿用现有 `ErrorCode` 体系。

**第一轮验收**：
- Flyway 在 demo profile 启动时干净迁移。
- 用 curl 能 list / 提交 / 审核评价；list / 提交 / 处理投诉；list / 发消息 / 关闭客服会话。

## 5. 跨模块协议

| 我提供给别人 | 他们提供给我 |
| --- | --- |
| `/api/merchant/ops/dashboard` 商家驾驶舱（依赖订单数据来源 = C/D 模块） | 订单完成事件触发 `order_state_log` 记录（C 已在做） |
| `/api/admin/governance/*` 评价/投诉处理后回写 `sys_audit_log` | 我读 `merchant_profile`、`merchant_store`、`order_main` 表（A/B/C 负责） |
| 评价审核屏蔽后，列表查询要排除 `hidden` 的评价（A 的店铺详情/B 的搜索都要 join） | A 提供"评价摘要"字段时不要直接 join `review_record`，而是从我新增的视图或 service 拿（避免别人重复实现过滤逻辑） |

**约定 1**：所有"对外只读"查询都走 service 方法，不让别人直接 join `review_record where status='published'`，保证我后期改审核逻辑时不破坏别人的页面。  
**约定 2**：投诉关闭/客服会话关闭后，不删除消息记录，只把 `closed_at` 写非空，方便统计。  
**约定 3**：所有写操作必须落 `sys_audit_log`，actor_type 取值 `user` / `merchant` / `admin`。
