# 风险与降级（成员 E）

## 1. 跨模块依赖风险

| 依赖项 | 风险 | 降级 |
| --- | --- | --- |
| 订单状态 `display_status = used`（C 已落地） | C 改了状态机命名导致评价入口失效 | 后端 `InteractionService` 校验时用枚举 `DisplayOrderStatus.USED.code()`，不在 SQL 里写魔法字符串 |
| 文件上传 `file_asset`（已落地） | 评价图片上传需要本地目录 `app.upload.dir` | Windows 本地统一走 `D:/aituan_runtime/uploads`；上传失败时评价仍可只发文字 |
| 商家身份解析（B/A 已实现） | 商家端接口需要 `CurrentUserContext.required().merchantId()` | 启动时检查；若 merchant_id 为空抛 `FORBIDDEN`，不要默默放过 |
| 后台审计日志（已落地） | 别人在 `sys_audit_log` 上加字段我没察觉 | 写操作只用 service 方法插入，不直接 INSERT；新增字段在我这里 fallback 为 null |

## 2. AI 能力降级

| 期望 AI 能力 | 实际降级方式 |
| --- | --- |
| 评价标签自动建议 | 在前端用固定标签池（如：味道好/出餐快/服务好/分量足/性价比高），最多让用户选 3 个 |
| 商家回复模板 | 后端 `sys_dict.support_template` 预置 5 条，前端下拉直接选 |
| 投诉违规识别 | 不做，所有投诉先入 pending 等待人工受理 |
| 评价违规识别 | 不做，依赖用户举报触发审核 |
| 统计趋势分析 | 不做，只展示原始 count |

## 3. 性能与数据量

- seed 演示数据 < 200 条评价 / 50 条投诉 / 50 个会话，count(*) 查询直接 OK。
- 商家端「我门店所有评价」用 `idx_review_store_status (store_id, status)` 加速。
- 后台端「待审核评价」按 `status` 过滤，已加 `idx_review_status`。
- 会话消息分页用 `(session_id, id)` 联合索引，按 id desc 翻页，避免 offset 越大越慢。

## 4. 状态机非法跃迁

后端必须拒绝并返回 `ORDER_STATE_INVALID`：

- 投诉：`pending → resolved`（必须先 accept）；`closed → 任何`
- 客服会话：`closed → 任何消息发送`
- 评价审核：`hidden → hide`、`published → restore`（重复操作直接返回原状态，不报错；非法跃迁报错）
- 评价重复回复：返回原回复（幂等）

## 5. 跨端联调阻塞应急

| 场景 | 应急 |
| --- | --- |
| 后端接口未上线，前端 demo 阻塞 | 用户端在 `support_repository.dart`、`complaint_repository.dart`、`review_repository.dart` 中预置 `MOCK` 开关，传 `--dart-define=MOCK_E=true` 时返回内存数据 |
| 商家端联调阻塞 | 第一轮先把所有 `/api/merchant/ops/*` 用 curl 文档化，让队友先按文档对齐 |
| seed 数据冲突 | 我自己的演示数据全部用 `MEM_E_` 前缀的业务编号（如 `MEM_E_REV_001`），便于在群里识别归属 |

## 6. 工具与构建风险

- 本地构建与部署说明统一沿用 Windows/D 盘脚本路径，APK 输出到 `D:/aituan_release/apk/aituan-user-debug.apk`。
- Windows 执行 PowerShell 脚本时若发现新增表导致迁移失败，立即在群里同步，不要自行改迁移编号。所有迁移编号调整都必须从负责人这里统一给出。
- 数据库迁移必须同时兼容 MySQL 8 与 H2（`MODE=MySQL`）空库执行；不要使用 `AFTER`、触发器、存储过程、JSON 专有函数等未经双端验证的单方言写法，否则会导致本地测试或服务器部署其中一端失败。

## 7. 不做项（明确划界，避免被拉走）

- 不做积分、勋章、KOL 评价人证体系
- 不做投诉赔付/退款资金流
- 不做实时 WebSocket 推送（会话消息靠列表刷新和下拉刷新）
- 不做评价的"图片审查"AI
- 不做后台日志的 ELK 接入

这些项写到 `docs/后续功能待办.md`，后续阶段再做。
