## 4. 下次建议继续做什么

### 优先级 1：创建 Android 模拟器并运行 Flutter integration_test

如果用户确认允许下载 SDK 组件和创建 AVD，执行：

```bash
"/d/soft/Android/Sdk/cmdline-tools/latest/bin/sdkmanager.bat" \
  "platforms;android-35" \
  "system-images;android-35;google_apis;x86_64"
```

创建 AVD：

```bash
"/d/soft/Android/Sdk/cmdline-tools/latest/bin/avdmanager.bat" create avd \
  --name aituan_api35 \
  --package "system-images;android-35;google_apis;x86_64" \
  --device "pixel_6" \
  --force
```

启动模拟器：

```bash
"/d/soft/Android/Sdk/emulator/emulator.exe" -avd aituan_api35
```

运行端到端测试：

```bash
cd apps/user_app
flutter test integration_test -d emulator-5554
```

注意：下载 / 创建 AVD 会占用数 GB 磁盘空间，应先让用户确认。

### 优先级 2：运行最终验证

建议按顺序运行：

```bash
mvn -B -f services/backend/pom.xml verify
npm test --prefix apps/merchant_web
npm run test:coverage --prefix apps/merchant_web
npm test --prefix apps/admin_web
npm run test:coverage --prefix apps/admin_web
cd apps/user_app && flutter test --coverage
```

如果 Android 模拟器可用，再补：

```bash
cd apps/user_app && flutter test integration_test -d emulator-5554
```

### 优先级 3：视情况调整 CI

如果 GitHub Actions 中 Android emulator 太慢或不稳定，可以把 integration_test 拆成单独 job，或者先设为手动触发。但目前配置已经满足“CI 执行端到端测试”的课程要求。
