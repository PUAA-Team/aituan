# 爱团后端部署与联调说明（Stage 4）

## 1. 文档目标

本文档记录后端编码阶段的本地开发、数据库初始化、接口验证和 Flutter 联调方式。当前后端尚未开始编码，本说明作为后续实施时必须遵守的部署与联调基线。

## 2. 本地环境建议

| 工具 | 建议版本 | 说明 |
| --- | --- | --- |
| JDK | 17 | Spring Boot 3.x 推荐版本 |
| MySQL | 8.x | 字符集 `utf8mb4` |
| Gradle | 使用 Wrapper | 避免全局版本不一致 |
| PowerShell | Windows 自带 | 项目脚本优先提供 `.ps1` |
| Flutter APP | `apps/user_app/` | 后端联调目标 |

## 3. 目录约定

```text
new/
├─ services/backend/          # Spring Boot 后端
├─ database/migrations/       # Flyway 建表脚本
├─ database/seeds/            # 演示数据脚本
├─ scripts/dev/start_backend.ps1
├─ scripts/build/build_backend.ps1
└─ docs/stage4/
```

当前 C 盘空间特别紧张，后端本地测试、打包、运行、临时日志和构建缓存都必须优先放在 D 盘英文路径，且不要直接散落在 D 盘根目录。本机没有 Docker Compose 环境，日常本地测试不使用 Docker Compose；Docker Compose 仅作为后续部署方式提供。

## 4. 配置文件规划

后端建议提供三套配置：

```text
services/backend/src/main/resources/
├─ application.yml
├─ application-dev.yml
├─ application-demo.yml
└─ application-test.yml
```

### 4.1 `application-dev.yml`

开发环境连接本地 MySQL，示例：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/aituan_dev?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: aituan
    password: aituan_dev_password
  flyway:
    enabled: true
    locations: classpath:db/migration
```

真实密码不要提交到 Git；如需本机私密配置，使用未纳入版本控制的 `application-local.yml` 或环境变量。

## 5. 数据库初始化流程

后端编码完成后，推荐流程：

1. 创建数据库：

```sql
CREATE DATABASE aituan_dev DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

2. 创建开发账号并授权。
3. 启动后端，让 Flyway 自动执行 `database/migrations` 对应的迁移脚本。
4. 执行 `database/seeds` 中的演示数据脚本。
5. 打开 Swagger，检查接口分组是否完整。

## 6. 本地启动脚本规划

### 6.1 D 盘运行目录

后端本地运行建议统一使用以下目录，避免占用 C 盘：

```text
D:/aituan_build/backend/      # 后端构建工作目录
D:/aituan_cache/gradle/       # Gradle 缓存，可由脚本临时指定
D:/aituan_runtime/backend/    # 后端运行日志和临时文件
D:/aituan_release/backend/    # 后端 jar 产物
```

这些目录都在 D 盘项目子目录下，不直接污染 D 盘根目录。若需要修改系统级 `GRADLE_USER_HOME` 或环境变量，必须先单独确认。

### 6.2 启动脚本

后续新增：

```text
scripts/dev/start_backend.ps1
```

职责：

1. 同步 `services/backend` 到 `D:/aituan_build/backend/`。
2. 将 Gradle 缓存和临时运行目录指向 D 盘会话级路径。
3. 在 D 盘工作目录使用 dev profile 启动：

```powershell
./gradlew bootRun --args='--spring.profiles.active=dev'
```

## 7. 构建脚本规划

后续新增：

```text
scripts/build/build_backend.ps1
```

职责：

1. 同步后端源码到 `D:/aituan_build/backend/`。
2. 使用 D 盘 Gradle 缓存执行测试：`./gradlew test`。
3. 构建 jar：`./gradlew clean bootJar`。
4. 复制 jar 到 `D:/aituan_release/backend/`。
5. 输出构建产物路径。

## 8. Docker Compose 部署方式

本机日常测试不使用 Docker Compose，但项目需要提供 Docker Compose 部署方式，方便后续在服务器或有 Docker Compose 环境的电脑上一键启动。

### 8.1 文件规划

```text
deploy/
├─ docker-compose.yml
├─ backend/
│  └─ Dockerfile
└─ README.md
```

### 8.2 服务规划

`docker-compose.yml` 至少包含：

1. `mysql`：MySQL 8，使用 named volume 保存数据。
2. `backend`：Spring Boot 后端镜像，连接 Compose 内部 MySQL。

后续可以扩展：Redis、Nginx、Adminer/phpMyAdmin。

### 8.3 数据保护要求

1. MySQL 数据必须保存在 named volume，例如 `aituan_mysql_data`。
2. 更新后端镜像、重启容器、重新执行 Compose 不得覆盖数据库数据。
3. Compose 初始化 SQL 只做首次建库，不做全表清空。
4. 数据库结构更新仍走 Flyway 增量迁移。
5. 演示数据脚本必须幂等，不能用 `TRUNCATE` 或无条件 `DELETE` 重灌。

### 8.4 Compose 示例方向

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: aituan
      MYSQL_USER: aituan
      MYSQL_PASSWORD: aituan_password
      MYSQL_ROOT_PASSWORD: root_password
    volumes:
      - aituan_mysql_data:/var/lib/mysql

  backend:
    build:
      context: ..
      dockerfile: deploy/backend/Dockerfile
    depends_on:
      - mysql
    environment:
      SPRING_PROFILES_ACTIVE: demo
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/aituan?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
      SPRING_DATASOURCE_USERNAME: aituan
      SPRING_DATASOURCE_PASSWORD: aituan_password
    ports:
      - "8080:8080"

volumes:
  aituan_mysql_data:
```

## 9. 接口验证顺序

### 9.1 第一轮后端自测

1. `GET /actuator/health` 或自定义健康检查。
2. `GET /v3/api-docs`。
3. `POST /api/open/auth/user/login/password`。
4. `GET /api/app/discovery/home`。
5. `GET /api/app/discovery/modules/takeaway`。
6. `GET /api/app/discovery/stores/search?keyword=汉堡`。
7. `GET /api/app/discovery/stores/{storeId}`。
8. `POST /api/app/trade/checkout/preview`。
9. `POST /api/app/trade/orders`。
10. `POST /api/app/trade/orders/{orderId}/pay`。

### 9.2 第二轮 Flutter 联调

按最小风险顺序替换前端 Mock：

1. 首页模块和猜你喜欢。
2. 搜索结果。
3. 商家详情和商品详情。
4. 登录注册。
5. 确认订单和模拟支付。
6. 订单列表和订单详情。
7. 收藏、消息、评价。

每接入一组接口后都要运行：

```powershell
flutter analyze
flutter test
```

如果改动影响用户端界面，还需要重新打包 APK。

## 10. 前端联调配置规划

Flutter 当前有：

```text
apps/user_app/lib/core/network/app_api_client.dart
```

后续应增加：

1. API 基础地址配置，例如 `http://10.0.2.2:8080` 供 Android 模拟器访问本机。
2. API 地址必须支持通过 `--dart-define=API_BASE_URL=...` 覆盖，避免改代码才能换后端。
3. Token 注入。
4. 统一响应解析：`code/message/data/requestId`。
5. 错误映射和登录失效处理。
6. Repository 逐模块替换 Mock 数据源。

推荐启动方式：

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080
```

推荐打包方式：

```powershell
flutter build apk --debug --dart-define=API_BASE_URL=http://192.168.1.100:8080
```

## 11. 演示数据要求

后端 demo profile 必须保证以下页面无需人工造数据即可展示：

1. 首页八模块。
2. 外卖、团购、酒店、休闲娱乐、电影演出、丽人医美、景点门票、洗脚模块页。
3. 搜索“汉堡”“电影”“洗脚”“酒店”都有结果。
4. 至少两个外卖商家，每个商家有多个分类商品。
5. 至少七类非外卖商家，每类至少一个商家。
6. 订单列表包含未支付、待完成、未使用、已使用。
7. 非外卖未使用订单包含券码和二维码载荷。
8. 消息页包含订单通知、系统通知、互动提醒。
9. 已使用订单可以发布评价。

## 12. 风险处理

1. 如果 MySQL 连接失败，先检查数据库、账号、端口和 profile，不要改系统环境变量。
2. 如果 Flutter 模拟器访问不到本机后端，Android 模拟器使用 `10.0.2.2`，真机使用电脑局域网 IP。
3. 如果接口字段变更，先更新 Stage4 文档和 OpenAPI，再改 Flutter DTO。
4. 如果 C 盘空间不足，优先把构建目录或缓存放 D 盘；涉及环境变量变更前需确认。
5. 不要把数据库密码、JWT secret、邮箱授权码提交到 Git。
