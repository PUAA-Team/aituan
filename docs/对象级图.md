# 对象级图（四张）

> 根据项目实际代码生成，将组件级图中的抽象组件替换为真实类对象与方法。
> 项目说明：订单、支付（模拟）、券码、库存、退款集中在 `TradeService` + `TradeRepository`；评价/审核集中在 `InteractionService`；通知统一走 `StationMessagePublisher`。

## 组件 → 对象（真实类）映射

| 组件级图里的组件 | 项目中的真实对象 / 方法 |
| --- | --- |
| 订单服务 | `TradeService` |
| 库存服务 | `TradeService.loadTradeContext/reserveStock` → `TradeRepository.decreaseSkuStock` |
| 支付服务 / 支付模拟服务 | `TradeService.pay` → `TradeRepository.markPaymentSuccess`（同步模拟支付，无回调） |
| 券码服务 | `TradeService.pay/redeemVoucher` → `TradeRepository.insertVoucher/findVoucherByCode/setOrderUsed/markVoucherRefunded` |
| 优惠券 | `CouponService.redeem / releaseByOrder` |
| 会员成长值 | `MemberService.addOrderCompletionGrowth / refundOrderGrowth / addReviewGrowth` |
| 通知服务 | `StationMessagePublisher.order / review` |
| 评价服务 | `InteractionService.submitReview / merchantReply` |
| 审核服务 | `InteractionService.adminAudit` + `InteractionRepository.updateReviewStatus` |

## 图1：用户购买非外卖服务并获得券码凭证（对象级顺序图）

```mermaid
sequenceDiagram
    actor 用户
    participant TradeService
    participant TradeRepository
    participant CouponService
    participant StationMessagePublisher

    用户->>TradeService: createOrder(CreateOrderRequest) 选择服务并提交购买
    TradeService->>TradeRepository: loadTradeContext(): findStore/findItem/findSkuByItem 校验价格、库存、限购、业务类型
    alt 库存不足 / 商品不属于门店 / 业务类型不符
        TradeRepository-->>TradeService: BusinessException 校验失败
        TradeService-->>用户: 返回校验失败信息
    else 校验通过
        TradeService->>TradeRepository: reserveStock(): decreaseSkuStock 预留库存
        TradeService->>TradeRepository: insertOrder() / insertOrderItem() 创建非外卖订单
        TradeService->>CouponService: redeem(couponId, orderId) 核销优惠券
        TradeService-->>用户: 返回待支付订单
        用户->>TradeService: pay(orderId, PayOrderRequest) 发起模拟支付
        TradeService->>TradeService: 校验订单状态(paymentStatus=UNPAID 且未退款)
        alt 订单已支付（重复支付）
            TradeService-->>用户: 幂等返回订单详情
        else 首次支付成功
            TradeService->>TradeRepository: markPaymentSuccess 标记支付成功（模拟支付）
            TradeService->>TradeRepository: insertVoucher 生成唯一券码 + 二维码
            TradeService->>TradeRepository: updateOrderAfterServicePaid 更新订单为已支付待使用
            TradeService->>StationMessagePublisher: order() 发布券码生成站内信
            TradeService-->>用户: 返回券码凭证（券码、有效期、使用规则）
            用户->>TradeService: getOrderDetail(orderId) 查看订单详情/券码
            TradeService-->>用户: 展示券码信息
        end
    end
```

## 图2：用户预约到店/团购服务并由商家核销完成服务（对象级状态图）

```mermaid
flowchart TD
    subgraph U["用户"]
        A([开始]) --> B[提交预约：选择门店/日期/时段]
        I[到店出示券码/预约凭证]
        Z([结束])
    end

    subgraph TS["TradeService"]
        C{upsertBooking 校验订单类型与预约信息}
        D[BusinessException 提示失败]
        F[confirmBookingForStaff 商家确认预约]
        J[redeemVoucher 商家发起核销]
        K{findVoucherByCode 校验券码}
        L[拒绝核销并提示]
    end

    subgraph TR["TradeRepository"]
        E[upsertBooking 写入预约申请]
        G[confirmBooking 占用资源生成预约凭证]
        M[setOrderUsed 核销成功]
    end

    subgraph MS["MemberService"]
        N[addOrderCompletionGrowth 发放成长值]
    end

    subgraph SP["StationMessagePublisher"]
        H[order 通知用户预约成功]
        O[order 通知用户服务完成]
    end

    B --> C
    C -->|外卖订单/信息为空| D
    D --> Z
    C -->|校验通过| E
    E --> F
    F -->|确认| G
    F -.->|改期：再次 upsertBooking| B
    F -->|拒绝/超时| D
    G --> H
    H --> I
    I --> J
    J --> K
    K -->|不存在/已核销/已退款/已过期| L
    L --> Z
    K -->|unused 且未过期| M
    M --> N
    N --> O
    O --> Z
```

## 图3：用户申请取消与退款，商家或平台处理退款（对象级状态图）

```mermaid
flowchart TD
    subgraph U["用户"]
        A([开始]) --> B[refundOrderForUser 提交取消/退款申请]
        Z([结束])
    end

    subgraph OPS["商家/平台"]
        O[refundOrderForStaff 人工退款]
    end

    subgraph TS["TradeService"]
        C{规则判断：是否已退款/是否已支付/是否可退}
        D[BusinessException 拒绝并提示]
        R[refundOrder 执行退款]
        S[restoreOrderStock 恢复库存]
    end

    subgraph TR["TradeRepository"]
        E[insertRefundRecord 创建退款记录]
        F[markOrderRefunded 更新订单为已退款]
        G[非外卖：markVoucherRefunded + cancelBookingForRefund<br/>券码失效并取消预约]
        H[increaseSkuStockByItem 释放库存]
    end

    subgraph CO["CouponService"]
        I[releaseByOrder 释放优惠券]
    end

    subgraph MS["MemberService"]
        J[refundOrderGrowth 回收成长值]
    end

    subgraph SP["StationMessagePublisher"]
        K[order 通知用户退款成功]
    end

    B --> C
    O --> C
    C -->|未支付/已退款/不可退| D
    D --> Z
    C -->|符合规则| R
    R --> E
    E --> F
    F --> G
    G --> I
    I --> S
    S --> H
    H --> J
    J --> K
    K --> Z
```

> 说明：组件级图里「商家审核 → 拒绝 → 平台复核」的多级审批，在真实代码中是**同步直接退款**（`refundOrder` 一次性完成，模拟退款 `MOCK-REFUND-xxx`），没有异步多级审批流，因此对象级图把两个入口（用户自助 / 商家平台人工）归并到同一个 `refundOrder`。

## 图4：用户完成订单后发布评价，商家回复，平台审核或治理评价（对象级顺序图）

```mermaid
sequenceDiagram
    actor 用户
    actor 商家
    actor 平台管理员
    participant InteractionService
    participant InteractionRepository
    participant MemberService
    participant StationMessagePublisher

    用户->>InteractionService: submitReview(orderId, ReviewCreateRequest) 提交评价
    InteractionService->>InteractionService: 校验评分(1~5)
    InteractionService->>InteractionRepository: findOrderForReview 校验订单状态与评价资格
    alt 订单未完成（非 USED）
        InteractionService-->>用户: 拒绝发布（订单完成后才能评价）
    else 资格校验通过
        InteractionService->>InteractionRepository: findReviewByOrder 校验重复评价
        alt 已评价
            InteractionService-->>用户: 幂等返回已发布评价
        else 首次评价
            InteractionService->>InteractionRepository: insertReview 发布评价
            InteractionService->>InteractionRepository: markOrderReviewed 标记订单已评价
            InteractionService->>MemberService: addReviewGrowth 发放成长值
            InteractionService-->>用户: 评价发布成功
        end
    end

    商家->>InteractionService: merchantReply(reviewId, MerchantReviewReplyRequest) 查看评价并提交回复
    InteractionService->>InteractionRepository: findReviewForMerchant / findReplyByReview 校验回复资格
    alt 已回复
        InteractionService-->>商家: 幂等返回原回复
    else 回复内容为空
        InteractionService-->>商家: 回复内容不能为空
    else 回复内容合格
        InteractionService->>InteractionRepository: insertReply + markReviewReplied 保存并公开回复
        InteractionService->>StationMessagePublisher: review() 通知用户商家已回复
        StationMessagePublisher-->>用户: 推送回复通知
    end

    平台管理员->>InteractionService: adminAudit(reviewId, AdminReviewAuditRequest) 审核举报/抽检评价
    InteractionService->>InteractionService: 解析审核动作(pass/hide)
    alt 动作合法（pass 通过 / hide 屏蔽）
        InteractionService->>InteractionRepository: updateReviewStatus 执行处置
        InteractionService->>StationMessagePublisher: review() 通知用户审核结果
        InteractionService->>InteractionRepository: insertReviewAuditLog + markReportsHandled 记录审计并结单
        InteractionService-->>平台管理员: 处置完成
    else 动作不合法
        InteractionService-->>平台管理员: 审核动作不正确
    end
```
