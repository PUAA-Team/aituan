# Stage5 App 位置、设置与图片上传实施说明

## 实施范围

本阶段补齐用户端尚未明确分配的基础入口，并完善位置和图片上传能力：

1. 用户端“我的”页新增设置和关于爱团入口。
2. 首页右上角消息按钮改为可点击，进入消息页。
3. 统一 App 消息提示，新的 SnackBar 会覆盖旧提示，避免连续排队展示。
4. App 获取用户定位，将经纬度传给发现页、模块页、搜索、商户详情和商品详情接口。
5. 后端基于用户经纬度和商户经纬度计算距离与预计时间；无地图 Key 时使用本地 Haversine 距离估算。
6. 图片上传支持 `local` 与 `lskypro` 两种策略，默认仍为本地上传。

## 用户端改动

### 设置与关于爱团

新增页面：

- `apps/user_app/lib/features/profile/presentation/settings_page.dart`
- `apps/user_app/lib/features/profile/presentation/about_page.dart`

路由：

- `/settings`：设置页。
- `/about`：关于爱团页。

设置页包含账号摘要、消息提醒、位置服务、清理缓存、隐私设置占位和退出登录。关于页展示产品介绍、版本、服务理念、核心能力、用户协议和隐私政策入口占位。

### 消息入口与提示覆盖

首页头部右上角通知按钮进入 `Routes.message`，该路由复用 `MainShell(initialIndex: 1)` 打开消息页。

新增统一提示方法：

- `apps/user_app/lib/core/widgets/app_toast.dart`

`showAppSnackBar(context, message)` 内部先清除旧 SnackBar，再展示新 SnackBar，解决连续触发提示时排队显示过久的问题。

### 定位与距离展示

新增定位状态和服务：

- `apps/user_app/lib/features/location/application/location_service.dart`
- `apps/user_app/lib/features/location/application/location_state.dart`
- `apps/user_app/lib/features/location/application/location_scope.dart`

App 启动首页后会尝试获取一次定位。用户点击首页位置文案可重新定位；定位成功时展示定位到的位置文字。模拟器或设备定位不可用时，App 静默使用“北航学院路校区”坐标并直接显示该位置，不向用户展示定位失败提示。

发现页相关请求会自动携带：

```text
latitude=<用户纬度>&longitude=<用户经度>
```

商户模型新增字段：

- `estimatedTimeText`
- `longitude`
- `latitude`

商户聚合卡、外卖商户页和到店服务商户页展示格式为：

```text
距离 · 约X分钟
```

未获取定位或商户缺少经纬度时，继续展示原有 `distance_text`。

## 后端改动

### 发现接口位置参数

以下接口新增可选参数 `latitude`、`longitude`：

- `GET /api/app/discovery/home`
- `GET /api/app/discovery/modules/{moduleCode}`
- `GET /api/app/discovery/stores/search`
- `GET /api/app/discovery/stores/{storeId}`
- `GET /api/app/discovery/stores/{storeId}/items`
- `GET /api/app/discovery/items/{itemId}`

`StoreCardView` 新增返回字段：

- `estimatedTimeText`
- `longitude`
- `latitude`

### 距离计算策略

`MapDistanceService` 负责位置相关能力：

- 默认使用本地 Haversine 直线距离，并按经验速度估算预计时间。
- 列表排序直接使用用户坐标和商家坐标做本地距离计算，避免批量调用高德导致配额消耗。
- `aituan.map.provider=amap` 且配置高德 Web API Key 时，商家保存地址可调用高德地理编码服务，将文字地址解析为经纬度。
- 高德调用失败时自动回退本地估算，不向用户暴露地图服务错误。

演示种子数据为 `merchant_store` 补充了经纬度，商家端也可以在门店资料中维护经度、纬度，保证 demo 数据可计算距离。

## 图片上传策略

原有上传入口不变：

- `POST /api/common/files/upload`
- 头像、店铺封面、商品封面、认证材料等仍统一调用 `FileStorageService.save(...)`

新增上传策略：

- `local`：默认策略，图片保存到本地上传目录，返回 `/api/common/files/...`。
- `lskypro`：调用 LskyPro `/upload` 接口，返回外部图床地址。

新增后端类：

- `ImageStorageProperties`
- `ImageStorageClient`
- `StoredImage`
- `LocalImageStorageClient`
- `LskyProImageStorageClient`

`FileStorageService` 保留统一校验、业务类型归一化、`file_asset` 记录写入和本地文件读取能力。

## 安全与配置约束

- `.config` 已加入 `.gitignore`，真实 API Key 不提交 Git。
- `.config.example` 只保存占位配置。
- 默认 `aituan.upload.strategy=local`，没有图床密钥也可以正常本地开发。
- 只有明确设置 `aituan.upload.strategy=lskypro` 时才会调用外部图床。
- LskyPro token 缺失或上传失败时返回明确错误，不静默回退到本地，避免误判外部上传结果。

## 影响范围

本轮不做完整地图选点 UI，不做配送员实时轨迹，也不改变现有订单、支付、配送推进接口语义。位置能力只覆盖用户当前位置、商户经纬度、距离和预计时间展示的最小闭环。
