## 0. 总体原则

1. 本轮以“用户实际发现的问题”为准，不把问题仅当作演示优化。
2. 登录页不再预填账号密码，但 seed 演示账号继续保留，文档继续列出演示账号。

5. 外卖费用、餐具、配送费属于业务模型调整，需要数据库、后端、商家端、用户端一起改，不能只改前端展示。

## 4. 问题 3：登录状态保存，默认保存 token 自动登录

### 最终问题描述

用户希望登录后默认自动保存登录态，下次打开无需重新登录。最终确认：不保存明文密码，只保存 token；token 有效期加长；APP 默认保存 token 自动登录；Web 商家端/后台端保存 token，同时保存账号名用于下次展示/填充账号，不保存密码。token 失效后回到登录页，不用账号密码静默登录。

### 当前定位

- APP 登录态：`apps/user_app/lib/app/app_state.dart:6-55`
  - token 只存在内存。
- APP 启动页：`apps/user_app/lib/features/auth/presentation/splash_page.dart:6-91`
  - 没有读取本地 token，也没有自动校验。
- APP 登录后状态写入：`apps/user_app/lib/features/auth/presentation/login_page.dart:251-260`
  - 只写入 `AppState`。
- 后端 token 校验：`services/backend/src/main/java/com/aituan/auth/AuthService.java:92-102`
  - 已有 token check 能力。
- Web 商家端：`apps/merchant_web/src/api.ts:29-48`
  - 已保存 token 到 localStorage，但没有保存账号名。
- Web 后台端：`apps/admin_web/src/api.ts:33-52`
  - 已保存 token 到 localStorage，但没有保存账号名。
- JWT 有效期配置：`services/backend/src/main/resources/application.yml:35-38`
  - `AITUAN_JWT_TTL_SECONDS` 默认当前为 604800 秒，即 7 天。

### 修复计划

1. APP 引入安全持久化依赖，建议用 `flutter_secure_storage` 保存 token。
2. 后端 JWT 默认有效期调整为更长周期，建议默认 30 天，并仍允许通过 `AITUAN_JWT_TTL_SECONDS` 覆盖。
3. APP 登录成功后保存 token 和必要用户资料缓存。
4. SplashPage 启动流程改造：
   - 读取本地 token；
   - token 不存在：显示登录/游客入口；
   - token 存在：调用 `/api/open/auth/token/check`；
   - token 有效：恢复 `AppState` 并进入主页；
   - token 无效或接口返回未授权：清除本地 token，停留/跳转登录页。
5. APP 退出登录时同步清除本地 token。
6. Web 商家端/后台端登录成功后保存账号名到 localStorage，例如 `aituan_merchant_account`、`aituan_admin_account`。
7. Web 登录页初始账号名从 localStorage 读取，密码仍为空。
8. token 过期后统一清 token 并回登录页。

## 5. 问题 4：接入 QQ 邮箱 SMTP 验证码

### 最终问题描述

当前邮箱验证码只在后端生成并直接返回给前端，前端还自动填入验证码。最终确认：接入 QQ 邮箱 SMTP，SMTP 参数通过环境变量放到 `.config`；暂时保留开发环境返回验证码的能力，但要放到后续修改文档里标记为将来移除；验证码发送要增加同客户端 60 秒限制。

关于 reset scene：`reset` 和 `reset_password` 本质只是数据库中区分验证码用途的字符串，没有业务区别。为了语义清楚，建议统一为 `reset_password`，后端和前端保持一致即可。

### 当前定位

- 后端发送验证码：`services/backend/src/main/java/com/aituan/auth/AuthService.java:28-32`
  - 只生成、入库、返回验证码。
- 后端重置密码校验：`services/backend/src/main/java/com/aituan/auth/AuthService.java:83-85`
  - 当前使用 scene `reset`。
- APP 发送找回密码验证码：`apps/user_app/lib/features/auth/presentation/login_page.dart:236-242`
  - 当前使用 scene `reset_password`。
- 后端 DTO：`services/backend/src/main/java/com/aituan/auth/AuthDtos.java:8-10`
  - 当前 response 包含 `code`。
- 后端依赖：`services/backend/pom.xml:25-74`
  - 当前没有 `spring-boot-starter-mail`。
- 后端配置：`services/backend/src/main/resources/application.yml:1-56`
  - 当前没有 mail 配置。

### 修复计划

1. 引入 `spring-boot-starter-mail`。
2. 在 `application.yml` 中增加邮件配置，并全部从环境变量读取：
   - SMTP host；
   - SMTP port；
   - username；
   - authorization code/password；
   - from address；
   - from name；
   - 是否启用 SMTP；
   - 是否在开发环境返回验证码。
3. `.config` 只由用户本地维护，不提交；文档只写变量名，不写真实值。
4. 新增邮件发送服务，负责组装验证码邮件并调用 SMTP。
5. `sendEmailCode()` 流程改为：校验发送频率 → 生成验证码 → 入库 → 邮件发送 → 返回发送状态和过期时间。
6. 发送频率限制：
   - 前端按钮 60 秒倒计时，防止同一客户端重复点击；
   - 后端按邮箱 + scene 做 60 秒限制；
   - 如能拿到客户端 IP/设备标识，再按客户端维度做限制。
7. reset scene 统一为 `reset_password`。
8. 暂时保留开发环境返回验证码能力，但通过配置开关控制；生产/服务器部署默认不返回验证码。
9. 更新 APP：真实发送时不再自动填验证码，只提示“验证码已发送，请查看邮箱”。开发返回验证码时可保留调试提示。
10. 将“未来移除开发环境返回验证码”写入 `docs/后续功能待办.md`。

## 7. 问题 6：首页推荐显示不全，也不是无限刷新

### 最终问题描述

首页推荐当前不是无限滚动，只是在已经拿到的 12 条里逐步显示。最终确认：要做无限滚动分页加载，注意不卡顿。推荐可以循环，但不要太近地重复推荐；同一商家的不同商品也不要太近地连续推荐。推荐算法后续还要继续完善，需要记录后续待办。

### 当前定位

- 首页接口内嵌推荐：`services/backend/src/main/java/com/aituan/discovery/DiscoveryService.java:41`
  - 固定 `recommendations(1, 12, ...)`。
- 推荐分页服务：`services/backend/src/main/java/com/aituan/discovery/DiscoveryService.java:48-68`
  - 已支持 page/pageSize。
- APP 首页只展示本地数量：`apps/user_app/lib/features/home/presentation/home_page.dart:30`、`apps/user_app/lib/features/home/presentation/home_page.dart:79`
- APP 滚动加载：`apps/user_app/lib/features/home/presentation/home_page.dart:180-188`
  - 只增加 `_visible`，不请求下一页。
- APP Repository 有推荐接口：`apps/user_app/lib/features/home/data/backend_app_repository.dart:77`
  - 但当前首页没有用它做分页。

### 修复计划

1. APP 首页状态改造：
   - 推荐列表；
   - 当前页码；
   - pageSize；
   - 是否正在加载更多；
   - 是否还有更多；
   - 已展示 itemId 集合；
   - 最近展示的 storeId 队列。
2. 初次加载：继续用首页接口拿模块和第一页推荐。
3. 滚动到底：调用推荐分页接口追加下一页。
4. 卡顿控制：
   - 加载更多时只显示底部小 loading，不全页 loading；
   - 避免重复 setState；
   - 防止滚动监听重复触发并发请求。
5. 循环推荐策略：
   - 到最后一页后可从第一页重新取，但前端要过滤近期已出现 itemId；
   - 同一个 storeId 近期出现过时，尽量后移；
   - 如果可选内容不足，再允许重复。
6. 后端推荐排序短期先用混合策略：排序、销量、距离等组合；后续完善推荐算法写入 `docs/后续功能待办.md`。
