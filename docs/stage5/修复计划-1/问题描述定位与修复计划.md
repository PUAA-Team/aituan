## 1. 清除所有地方的默认账号密码填充

### 问题描述

当前用户端、商家端、后台端登录页都存在默认账号/密码填充。这样虽然方便演示，但会造成两个问题：

1. 真实使用时看起来像账号密码被系统默认保存，体验不正式。
2. 如果部署到公网环境，登录页直接暴露演示账号和密码，不安全。

### 代码定位

- 用户端 APP 登录页：`apps/user_app/lib/features/auth/presentation/login_page.dart:25-28`
  - `_account` 默认是 `18800001111`。
  - `_email` 默认是 `user@example.com`。
  - `_password` 默认是 `123456`。
- 用户端切换注册/找回密码模式时还会重新填默认邮箱/手机号：`apps/user_app/lib/features/auth/presentation/login_page.dart:263-277`
  - 注册模式会把手机号重置为 `18800001111`。
  - 注册/找回密码会把邮箱重置为 `user@example.com`。
- 商家端登录页：`apps/merchant_web/src/pages/LoginPage.vue:15-16`
  - `account = demo_merchant`
  - `password = 123456`
- 后台端登录页：`apps/admin_web/src/pages/LoginPage.vue:13-14`
  - `account = demo_admin`
  - `password = 123456`
- 种子数据仍保留演示账号：`database/seeds/R__seed_demo_data.sql:8-23`
  - 用户、后台和多个商家演示账号密码均为 `{noop}123456`。

### 待确认点

1. “清除所有地方的默认账号密码填充”是否只清除登录表单预填？

   对

2. seed 里的演示账号是否继续保留？我建议保留 seed 演示账号，但不要在登录框自动填出。

   对

3. 文档里是否继续展示演示账号？如果文档面向本地演示，可以展示；如果面向生产部署，需要明确“仅本地演示使用”。

   继续

2. 用户端：切换注册/找回密码模式时不要自动填 `18800001111/user@example.com`，只保留用户已输入内容。
3. 商家端/后台端：登录页 `account/password` 初始值改为空。
4. 如果确认要隐藏入驻默认密码提示，则同步修改商家入驻提交成功文案。
5. 保留 seed 演示账号，但在 README/部署文档中区分“演示账号”和“生产部署不要使用默认密码”。

## 3. 登录状态保存：默认保存密码 + 自动登录

### 问题描述

用户希望登录状态默认保存，最好打开应用后自动登录。当前 APP 端登录态只保存在内存里，关闭/重启应用后会丢失。商家端和后台端 Web 已经把 token 存到 `localStorage`，刷新页面通常不会丢登录态，但没有保存密码功能。

### 代码定位

- APP 全局状态：`apps/user_app/lib/app/app_state.dart:6-55`
  - `_token` 只存在内存中。
  - `login()` 只更新内存状态。
  - `logout()` 只清内存状态。
- APP 启动页：`apps/user_app/lib/features/auth/presentation/splash_page.dart:6-91`
  - 没有读取本地 token。
  - 没有调用 token 校验接口。
- APP 登录后写状态：`apps/user_app/lib/features/auth/presentation/login_page.dart:251-260`
  - `_applySession()` 只调用 `AppScope.of(context).login(...)`。
- APP 依赖：`apps/user_app/pubspec.yaml:9-18`
  - 当前没有 `shared_preferences` 或 `flutter_secure_storage`。
- 后端已有 token 校验：`services/backend/src/main/java/com/aituan/auth/AuthService.java:92-102`
  - `checkToken(CurrentUser currentUser)` 可以校验并返回用户资料。
- Web 商家端 token：`apps/merchant_web/src/api.ts:29-48`
  - 使用 `localStorage` 保存 `aituan_merchant_token`。
- Web 后台端 token：`apps/admin_web/src/api.ts:33-52`
  - 使用 `localStorage` 保存 `aituan_admin_token`。

### 待确认点

1. 是否真的要“保存密码”？从安全角度不建议保存明文密码，建议保存 token，并在 token 有效期内自动登录。

   就是保存token，token有效期长一点

2. APP 是否需要“记住密码”开关？还是默认保存 token 自动登录即可？

   默认保存token自动登录

3. Web 商家端/后台端是否也需要保存账号名，用于下次自动填账号但不填密码？

   保存token，也保存账户名

4. token 过期后是否回到登录页，还是尝试用保存的账号密码静默登录？后者不推荐。

   用前者。

### 修复计划

1. APP 引入安全持久化方案，优先建议 `flutter_secure_storage` 保存 token。
2. 登录成功后保存 token 和必要的用户资料缓存。
3. SplashPage 启动时读取 token：
   - token 不存在：保持当前登录/游客入口。
   - token 存在：调用 `/api/open/auth/token/check`。
   - token 有效：恢复 `AppState` 并进入主页。
   - token 无效：清除本地 token，要求重新登录。
4. 退出登录时同步清除本地 token。
5. 如需 Web 也“默认自动登录”，确认当前 App.vue 是否会根据 localStorage token 拉取资料；如果没有，再补 Web 端 token 校验。

## 4. 接入 QQ 邮箱 SMTP 验证码

### 问题描述

当前注册/找回密码验证码没有真正发送邮件，而是后端生成验证码后直接返回给前端，前端还会把验证码自动填入输入框。这适合早期调试，但不符合真实邮箱验证码流程。

另外发现一个明显 bug：前端找回密码发送验证码使用的 scene 是 `reset_password`，但后端重置密码校验的是 `reset`，两边场景值不一致，可能导致找回密码验证码校验失败。

### 代码定位

- 后端发送验证码：`services/backend/src/main/java/com/aituan/auth/AuthService.java:28-32`
  - 生成 6 位随机码。
  - 写入 `iam_verification_code`。
  - 直接 `return new EmailCodeResponse(..., code, 600)`，把验证码返回给前端。
- 后端注册校验：`services/backend/src/main/java/com/aituan/auth/AuthService.java:42-44`
  - 使用 scene `register`。
- 后端重置密码校验：`services/backend/src/main/java/com/aituan/auth/AuthService.java:83-85`
  - 使用 scene `reset`。
- 前端发送验证码：`apps/user_app/lib/features/auth/presentation/login_page.dart:236-242`
  - 注册用 `register`。
  - 找回密码用 `reset_password`。
  - 返回后 `_code.text = code`，并提示 `验证码已发送：$code`。
- 后端 DTO：`services/backend/src/main/java/com/aituan/auth/AuthDtos.java:8-10`
  - `EmailCodeResponse` 当前包含 `code` 字段。
- Maven 依赖：`services/backend/pom.xml:25-74`
  - 当前没有 `spring-boot-starter-mail`。
- 配置文件：`services/backend/src/main/resources/application.yml:1-56`
  - 当前没有 `spring.mail.*` 或 QQ SMTP 配置。

### 待确认点

1. QQ 邮箱 SMTP 的发件邮箱、授权码、发件人名称是否由你提供，还是先预留环境变量？

   环境变量，放到.config

2. 开发环境是否继续允许“返回验证码给前端”方便调试？生产环境必须不返回。

   暂时保留，放到后续修改文档

3. 找回密码 scene 统一成 `reset` 还是 `reset_password`？建议统一成更清晰的 `reset_password`，但后端和历史数据都要同步。

   有啥区别？都行

4. 是否需要验证码发送频率限制，例如同一邮箱 60 秒内只能发一次、10 分钟内最多 5 次？

   行。然后同一个客户端60s才能发一次

### 修复计划

1. 后端引入 `spring-boot-starter-mail`。
2. 在 `application.yml` 增加 QQ SMTP 配置项，全部使用环境变量注入，避免提交邮箱授权码。
3. 新增邮件发送服务，例如 `EmailVerificationSender`。
4. `sendEmailCode()` 改为：生成验证码 → 入库 → 调 SMTP 发送 → 返回 `expireSeconds`，不返回 code。
5. APP `_sendCode()` 改为只提示“验证码已发送，请查看邮箱”，不自动填验证码。
6. 修复 reset scene 不一致问题。
7. 增加测试或至少手动验证：注册验证码、找回密码验证码、错误验证码、过期验证码。

## 6. 首页推荐显示不全，也不是无限刷新

### 问题描述

首页推荐当前只展示后端首页接口返回的一页推荐数据。前端虽然监听滚动并逐步增加可见数量，但只是从已加载的 12 条里多显示几条，并没有继续请求下一页。因此用户会感觉“显示不全”和“不是无限刷新”。

### 代码定位

- 后端首页接口固定内嵌 12 条推荐：`services/backend/src/main/java/com/aituan/discovery/DiscoveryService.java:41`
  - `recommendations(1, 12, latitude, longitude)`。
- 后端推荐分页接口存在：`services/backend/src/main/java/com/aituan/discovery/DiscoveryService.java:48-68`
  - 支持 `page/pageSize`。
- APP 首页初始只显示 6 条：`apps/user_app/lib/features/home/presentation/home_page.dart:30`、`apps/user_app/lib/features/home/presentation/home_page.dart:79`
  - `_visible = 6`。
  - `data.recommendations.take(_visible)`。
- APP 首页滚动加载：`apps/user_app/lib/features/home/presentation/home_page.dart:180-188`
  - 只把 `_visible` 增加 4，最多到当前 `data.recommendations.length`。
  - 不调用后端下一页。
- APP Repository 有推荐接口：`apps/user_app/lib/features/home/data/backend_app_repository.dart:77`
  - `fetchRecommendations()` 存在，但当前首页没有使用它做分页。

### 待确认点

1. “无限刷新”指无限滚动分页加载，还是下拉刷新时随机换一批？

   无限滚动分页加载，但是注意不要卡顿

2. 首页推荐排序希望按什么规则：距离、销量、综合排序、随机、还是混合？

   混合的吧，后续可以再改，后续文档写上要完善推荐算法

3. 是否需要“已到底”提示，还是可以循环推荐？

   可以循环推荐，但是不要太近地重复推荐。

   同时要注意，同一个商家的不同商品也不要太近地推荐

### 修复计划

1. 首页状态拆成推荐列表、当前页、是否还有更多、是否正在加载更多。
2. 初次加载仍调用首页接口拿模块和第一页推荐。
3. 滚动到底时调用推荐分页接口加载下一页，并追加到列表。
4. 下拉刷新时清空推荐分页状态，重新加载第一页。
5. 如果确认要随机刷新，可在后端推荐接口增加排序参数，或前端下拉刷新时请求不同页/随机种子。
