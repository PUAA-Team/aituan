# 爱团页面与路由清单（Stage 1）

## 1. 文档目标

本文档用于细化爱团三端页面结构、路由规则、页面职责、进入条件和关键跳转关系，作为前端骨架搭建、菜单设计、联调排期和测试清单的依据。

本文档对应以下架构文档：

- `docs/stage1/代码架构设计.md`
- `docs/stage1/API 分组设计.md`

## 2. 总体设计原则

1. **按业务流拆页面**：一个页面只承载一个主要任务，不做“大而全页面”。
2. **按模块分路由**：路由前缀与业务模块一致，便于后续拆文件。
3. **先 P0，后扩展**：先打通用户消费闭环、商家经营闭环、平台治理闭环。
4. **页面与接口一一对齐**：每个关键页面都能对应到明确 API 分组。
5. **页面文件不宜过大**：表单、弹窗、筛选器、卡片、时间线优先拆子组件。

## 3. 路由命名规则

## 3.1 用户端 Flutter 路由规则

1. 使用 `/模块/页面` 风格。
2. Tab 页面单独设一级路由。
3. 详情页统一使用 `:id` 占位思路表示，但 Flutter 实现时可转换为命名路由参数。

示例：

- `/home`
- `/search/result`
- `/merchant/detail/:storeId`
- `/order/detail/:orderId`

## 3.2 商家端 / 后台 Web 路由规则

1. 使用 `/模块/页面` 风格。
2. 列表页与编辑页拆开，不把所有逻辑塞到一个页面。
3. 核心管理页使用固定二级或三级路由。

示例：

- `/catalog/goods`
- `/catalog/goods/:itemId/edit`
- `/governance/merchant-audits/:auditId`

## 4.3 用户端核心跳转关系

### 4.3.1 消费主链路

```text
/splash
  -> /login 或 /home（游客进入）
  -> /module/:moduleCode 或 /search/result
  -> 外卖：/merchant/detail/:storeId（点单页）
  -> 外卖购物车上拉面板
  -> /checkout/confirm
  -> 模拟支付成功
  -> 外卖订单详情（待完成）

/home 或 /module/:moduleCode 或 /search/result
  -> 非外卖：/item/detail/:itemId 或 /merchant/detail/:storeId（商家信息页）
  -> /checkout/confirm
  -> 模拟支付成功
  -> 非外卖订单详情（未使用，展示券码/二维码）
  -> 已使用后 /review/publish/:orderId
```

### 4.3.2 个人中心链路

```text
/profile
  -> /orders
  -> /message/list
  -> /favorite
  -> /address/list
  -> /coupon/list
  -> /member/home
```

### 4.3.3 咨询链路

```text
/merchant/detail/:storeId
  -> /consult/session/:sessionId
/consult/list
  -> /consult/session/:sessionId
```

## 4.4 用户端页面拆分建议

1. 首页拆为顶部搜索定位、8 个模块入口、猜你喜欢推荐、底部 Tab 四块。
2. 模块展示页拆为模块搜索框、热门推荐、商铺聚合精选、横滑商品卡、加载更多五块。
3. 搜索结果页拆为搜索筛选区、八分类栏、商铺大卡、横滑命中商品/热门商品小卡、空状态推荐五块。
4. 商品详情页拆为图片区、价格标题区、规则区、店铺入口、底部操作栏五块。
5. 外卖商家详情页拆为短商家头部、下单/评价/商家切换、左侧分类锚点、右侧全部外卖商品分组列表、购物车上拉面板六块。
6. 非外卖商家详情页拆为完整商家信息、店内搜索、左侧分类锚点、右侧全部同类型商品/服务分组列表、评价摘要五块。
7. 确认订单页拆为地址/使用信息、商品明细、优惠券、支付方式、金额汇总、提交按钮六块。
8. 外卖订单详情和非外卖订单详情分开设计，非外卖详情必须展示券码或二维码核销区。

## 9. 风险与简化说明

1. 当前 Flutter 首包已确认包含 `item/detail` 商品/服务详情页；外卖商品不进入该页，非外卖商品/服务进入该页。
2. 配送跟踪、券码详情、预约详情、AI 助手和真实支付等页面先作为后续扩展，首包可保留入口但不完整展开。
3. 商家端的退款、核销、预约页均放在 P1，是为了先保证外卖交易和接单链路闭环。
3. 平台后台优先做审核、投诉、Banner、系统开关和日志，不在第一阶段强行铺满所有运营页。
4. 所有复杂页面后续都应拆出表单组件、筛选组件、状态组件，避免单个页面文件过长。
