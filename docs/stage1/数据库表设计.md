# 爱团数据库表设计（Stage 1）

## 1. 文档目标

本文档用于细化 `docs/stage1/代码架构设计.md` 中的后端数据层设计，输出可直接指导建表、写迁移脚本、接口联调和演示数据准备的数据库方案。

当前阶段采用以下原则：

1. **先满足 P0 闭环**：优先支持登录、搜索、下单、支付模拟、商家处理、配送模拟、评价、后台审核。
2. **统一交易模型**：外卖、团购、票券、预约尽量复用统一订单主表，差异字段下沉到扩展表。
3. **模块高内聚**：表按业务域分组，避免出现“全局大杂烩表”。
4. **实现从简**：本期不做复杂分库分表、不做复杂读写分离、不做复杂调度建模。
5. **可扩展**：P1/P2 需要的酒店、票务、更多 AI 能力可以直接增表，不推翻 P0 主结构。

## 2. 数据库总体约定

### 2.1 推荐环境

- 数据库：MySQL 8.x
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_0900_ai_ci`
- 时区：统一东八区
- 时间字段：统一 `datetime`
- 金额字段：统一 `decimal(10,2)`

### 2.2 命名规范

1. 表名统一使用 **小写 + 下划线**。
2. 主键统一命名为 `id`，类型建议 `bigint`。
3. 业务编号统一用 `*_no`，例如：`order_no`、`payment_no`、`delivery_no`。
4. 外键字段统一命名为 `xxx_id`。
5. 状态字段统一命名为 `status`，细分状态使用：
   - `audit_status`
   - `payment_status`
   - `delivery_status`
   - `refund_status`
6. 布尔类字段统一使用 `tinyint(1)`，命名为 `is_xxx`。

### 2.3 通用字段约定

除纯关系表外，大多数业务表建议包含以下字段：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | bigint | 主键 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |
| `created_by` | bigint/null | 创建人账号 ID |
| `updated_by` | bigint/null | 更新人账号 ID |
| `is_deleted` | tinyint(1) | 逻辑删除标记，0=否，1=是 |

### 2.4 逻辑删除原则

1. 用户、商家、商品、订单、评价、审核等核心表默认采用逻辑删除。
2. 登录日志、审计日志、AI 调用日志、支付记录等流水类表原则上**不物理删除**。
3. 关系已失效的数据优先改状态，不直接删除。

建议按以下 13 个数据域建表：

1. 账户与权限域
2. 用户域
3. 商家与门店域
4. 商品与服务域
5. 购物车域
6. 订单与支付域

10. 会员与营销域

## 5. 各业务域主表设计

## 5.1 账户与权限域

### 5.1.1 `iam_account`

账号主表，统一承载用户、商家、后台管理员的登录身份。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `account_no` | 账号编号 |
| `account_type` | 账号类型：user / merchant / admin |
| `login_name` | 登录名，可为空 |
| `phone` | 手机号 |
| `email` | 邮箱 |
| `password_hash` | 密码摘要，用户端可为空 |
| `status` | normal / disabled / locked |
| `last_login_at` | 最近登录时间 |
| `last_login_ip` | 最近登录 IP |

### 5.1.2 `iam_sms_code`

验证码发送与校验记录。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `target` | 手机号或邮箱 |
| `scene` | login / register / bind / sensitive_verify |
| `code` | 验证码 |
| `expire_at` | 过期时间 |
| `used_at` | 使用时间 |
| `status` | unused / used / expired |
| `send_channel` | sms / email / mock_console |

### 5.1.3 `iam_role`

角色表。

主要字段：`role_code`、`role_name`、`status`、`remark`。

### 5.1.4 `iam_permission`

权限点表。

主要字段：`permission_code`、`permission_name`、`permission_type`、`path`、`method`、`status`。

### 5.1.5 `iam_account_role`

账号与角色关系表。

主要字段：`account_id`、`role_id`。

### 5.1.6 `iam_role_permission`

角色与权限点关系表。

主要字段：`role_id`、`permission_id`。

## 5.2 用户域

### 5.2.1 `user_profile`

用户资料表。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `account_id` | 对应 `iam_account.id` |
| `nickname` | 昵称 |
| `avatar_url` | 头像 |
| `gender` | 性别 |
| `birthday` | 生日 |
| `register_source` | app / invite / mock |
| `member_level_id` | 当前会员等级 |
| `growth_value` | 当前烟火值 |
| `status` | normal / disabled |

### 5.2.2 `user_address`

用户收货地址表。

主要字段：`user_id`、`contact_name`、`contact_phone`、`province`、`city`、`district`、`detail_address`、`longitude`、`latitude`、`tag_name`、`is_default`、`delivery_note`。

### 5.2.3 `user_favorite`

用户收藏表。

主要字段：`user_id`、`favorite_type`（merchant / item / service）、`target_id`、`favorite_at`。

## 5.3 商家与门店域

### 5.3.1 `merchant_profile`

商家主体表，表示商家经营主体。

主要字段：`merchant_no`、`account_id`、`merchant_name`、`contact_name`、`contact_phone`、`license_no`、`status`、`audit_status`、`settled_at`。

### 5.3.2 `merchant_qualification`

商家资质材料表。

### 5.3.3 `merchant_store`

门店表。

| 字段 | 说明 |
| --- | --- |

| `merchant_id` | 所属商家 |

门店图片表。

主要字段：`store_id`、`media_type`、`file_url`、`sort_order`。

### 5.3.5 `merchant_delivery_rule`

## 5.4 商品与服务域

### 5.4.1 `catalog_category`

类目表，支持平台统一管理。

主要字段：`parent_id`、`category_name`、`category_code`、`business_scope`、`sort_order`、`status`。

### 5.4.2 `catalog_item`

统一商品/服务主表。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `store_id` | 所属门店 |
| `category_id` | 类目 |
| `item_type` | takeaway / group_buy / hotel / ticket / beauty / entertainment / massage（首页入口展示为“洗脚”，业务承接洗脚按摩） |
| `item_name` | 名称 |
| `subtitle` | 副标题 |
| `price` | 售价 |
| `original_price` | 原价 |
| `cover_url` | 封面图 |
| `description` | 详情说明 |
| `sales_count` | 销量 |
| `status` | draft / on_sale / off_sale / sold_out |
| `support_refund` | 是否支持退款 |

### 5.4.3 `catalog_item_media`

商品/服务图集表。

主要字段：`item_id`、`file_url`、`sort_order`、`media_type`。

### 5.4.4 `catalog_sku`

商品规格表，主要用于外卖商品、套餐、票型等。

主要字段：`item_id`、`sku_name`、`spec_snapshot`、`price`、`stock_qty`、`sales_count`、`status`。

### 5.4.5 `catalog_item_tag`

标签字典表。

主要字段：`tag_name`、`tag_type`、`status`、`sort_order`。

### 5.4.6 `catalog_item_tag_rel`

商品与标签关系表。

主要字段：`item_id`、`tag_id`。

### 5.4.7 `catalog_service_schedule`

日期/场次/预约资源表，用于酒店、票务、预约类能力。

主要字段：`item_id`、`schedule_date`、`time_slot`、`resource_type`、`total_qty`、`available_qty`、`price`、`status`。

> 说明：当前阶段不单独拆酒店房态表和电影场次表，统一先用 `catalog_service_schedule` 承接，后续复杂场景再细分。

## 5.5 购物车域

### 5.5.1 `cart`

购物车主表，按“用户 + 门店”分组。

主要字段：`user_id`、`store_id`、`cart_type`、`status`、`last_operated_at`。

### 5.5.2 `cart_item`

购物车明细表。

主要字段：`cart_id`、`item_id`、`sku_id`、`item_name_snapshot`、`price_snapshot`、`quantity`、`selected_options`、`status`。

## 5.6 订单与支付域

### 5.6.1 `order_main`

统一订单主表，是交易闭环核心表。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `order_no` | 订单编号 |
| `order_type` | takeaway / group_buy / hotel / ticket / booking |
| `user_id` | 下单用户 |
| `merchant_id` | 商家 |
| `store_id` | 门店 |
| `contact_name` | 联系人 |
| `contact_phone` | 联系方式 |
| `address_snapshot` | 地址快照，JSON 或文本 |
| `remark` | 用户备注 |
| `item_amount` | 商品总额 |
| `delivery_amount` | 配送费 |
| `service_amount` | 服务费 |
| `discount_amount` | 优惠金额 |
| `payable_amount` | 应付金额 |
| `payment_status` | unpaid / paying / paid / failed / timeout |
| `payment_method` | mock / wechat / alipay / card，当前阶段只启用 mock |
| `order_status` | created / paid / accepted / preparing / delivering / completed / cancelled / refunded |
| `fulfillment_status` | pending / processing / finished / closed |
| `display_status` | unpaid / pending_finish / unused / used，用于用户端订单列表聚合展示：未支付 / 待完成 / 未使用 / 已使用 |
| `close_reason` | 关闭原因 |
| `paid_at` | 支付时间 |
| `completed_at` | 完成时间 |

### 5.6.2 `order_item`

订单明细表。

主要字段：`order_id`、`item_id`、`sku_id`、`item_name_snapshot`、`sku_name_snapshot`、`quantity`、`deal_price`、`original_price`、`spec_snapshot`、`is_reviewed`。

### 5.6.3 `order_payment_record`

支付记录表。当前阶段只启用模拟支付，但字段保留真实支付扩展能力。

主要字段：`payment_no`、`order_id`、`payment_channel`、`payment_mode`（mock / wechat / alipay 等）、`request_amount`、`payment_status`、`fail_reason`、`callback_payload`、`callback_times`、`paid_at`。

### 5.6.4 `order_refund_record`

退款记录表。

主要字段：`refund_no`、`order_id`、`refund_reason`、`refund_amount`、`refund_status`、`merchant_audit_result`、`applied_at`、`finished_at`。

### 5.6.5 `order_coupon_usage`

订单使用优惠信息表。

主要字段：`order_id`、`user_coupon_id`、`coupon_template_id`、`discount_amount`。

### 5.6.6 `order_booking_record`

预约/日期/场次扩展表。

主要字段：`order_id`、`schedule_id`、`booking_date`、`time_slot`、`resource_snapshot`、`booking_status`、`verify_code`。预约类订单支付后可进入未使用状态，并通过 `verify_code` 或券码核销。

### 5.6.7 `order_voucher`

券码扩展表，用于团购券/票券和非外卖服务核销。

主要字段：`order_id`、`voucher_code`、`voucher_type`、`qr_payload`（可由券码动态生成）、`status`（unused / used / expired / refunded）、`effective_from`、`effective_to`、`verified_at`、`verified_by`。

### 5.6.8 `order_state_log`

订单状态流转日志表。

主要字段：`order_id`、`from_status`、`to_status`、`action_type`、`operator_id`、`operator_role`、`remark`、`created_at`。

## 6. 关键关系设计

## 6.1 账号与角色关系

```text
iam_account 1 --- n iam_account_role n --- 1 iam_role 1 --- n iam_role_permission n --- 1 iam_permission
```

## 6.2 商家经营关系

```text
merchant_profile 1 --- n merchant_store 1 --- n catalog_item 1 --- n catalog_sku
merchant_profile 1 --- n merchant_qualification
merchant_store 1 --- 1 merchant_delivery_rule
```

## 6.3 用户消费关系

```text
user_profile 1 --- n user_address
user_profile 1 --- n user_favorite
user_profile 1 --- n cart 1 --- n cart_item
user_profile 1 --- n order_main 1 --- n order_item
```

## 6.4 订单闭环关系

```text
order_main 1 --- n order_item
order_main 1 --- n order_payment_record
order_main 1 --- n order_refund_record
```

## 11. 风险与简化说明

1. `catalog_service_schedule` 当前统一承接酒店、票务、预约等资源，后续如果业务差异变大，再拆房态表、座位表、技师排班表。
2. `order_main` 当前承接所有订单类型，后续如果字段膨胀明显，再拆 `order_takeaway_ext`、`order_booking_ext` 等扩展表。
3. 配送模拟当前只做最小两张表，不引入骑手实体、不引入真实轨迹规划。
4. AI 当前只保留配置表和调用日志表，不在本阶段过早设计复杂知识库结构。
