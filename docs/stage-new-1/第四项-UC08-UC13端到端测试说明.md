# 第四项分工：UC08-UC13 端到端测试说明

## 1. 测试目标

本测试工程按照 `8.26任务分工(1).md` 的用例口径，自动验证以下六条跨角色业务闭环：

| 编号 | 场景 | 自动化范围 |
| --- | --- | --- |
| UC08 | 取消与退款 | 用户退款、商家退款、券码/预约/优惠券/库存释放 |
| UC09 | 评价治理 | 用户发布、商家回复、平台屏蔽与恢复 |
| UC10 | 投诉工单 | 用户提交、平台受理、处理、关闭和日志追溯 |
| UC11 | 客服与 AI | AI 降级回复、转人工、商家回复、平台介入 |
| UC12 | 会员优惠券 | 查看成长值、领券、下单抵扣、核销后成长 |
| UC13 | 商家经营维护 | 门店资料、履约规则、目录维护和上下架 |

用户端步骤通过真实 REST API 执行；商家端和后台端关键处理步骤使用 Chromium 操作真实 Vue 页面。所有请求均访问本轮自动启动的本地服务，不访问线上环境。

## 2. 工程结构与运行环境

测试工程位于 `tests/e2e/`，主要内容包括：

- `playwright.config.ts`：启动独立后端、商家端和后台端，配置报告与失败证据；
- `support/`：真实登录、统一 API 响应校验和业务场景夹具；
- `specs/`：UC08 至 UC13 六个场景文件；
- `artifacts/`：运行时生成的 HTML、JUnit、截图、视频和 trace，不提交 Git。

固定本地端口：

| 服务 | 地址 |
| --- | --- |
| Demo 后端 | `http://127.0.0.1:18080` |
| 商家端 | `http://127.0.0.1:15174` |
| 后台端 | `http://127.0.0.1:15175` |

后端使用 Demo profile 的 H2 内存数据库。Playwright 禁止复用已有服务，因此端口被占用时会直接失败，避免误操作开发库或线上数据。

## 4. 安装与执行

要求本机已具备 Java 17 或更高版本、Maven、Node.js、npm。首次执行：

```bash
npm ci --prefix apps/merchant_web
npm ci --prefix apps/admin_web
npm ci --prefix tests/e2e
npm run install:browser --prefix tests/e2e
```

无头运行全部场景：

```bash
npm test --prefix tests/e2e
```

显示浏览器运行：

```bash
npm run test:headed --prefix tests/e2e
```

打开最近一次 HTML 报告：

```bash
npm run report --prefix tests/e2e
```

六个 spec 串行执行，但每个场景会创建带时间戳和随机后缀的数据，不依赖其他 spec 的结果。

## 5. 报告与失败证据

- HTML 报告：`tests/e2e/artifacts/html-report/`
- JUnit XML：`tests/e2e/artifacts/results/junit.xml`
- 失败截图、视频、trace：`tests/e2e/artifacts/test-results/`

发生失败时，先看终端中的接口错误或页面断言，再打开 HTML 报告。trace 可查看浏览器操作、网络请求、DOM 快照和失败位置。

## 6. 常见问题

### 6.1 端口被占用

测试不会连接已存在的 `18080`、`15174`、`15175` 服务。请先结束占用端口的本地进程，再重新执行。

### 6.2 Chromium 未安装

执行：

```bash
npm run install:browser --prefix tests/e2e
```

Linux CI 如果缺少系统库，可由 CI/CD 负责人改用 `playwright install --with-deps chromium`；本分工不修改 workflow。

### 6.3 后端启动超时

先确认 `mvn -B -f services/backend/pom.xml test` 可以运行，并检查 Maven 下载是否被网络或代理阻断。Playwright 为后端预留 180 秒启动时间。

### 6.4 页面找不到动态数据

动态订单、评价、投诉和客服行使用业务 ID 生成的 `data-testid` 定位。如果接口已创建数据但页面没有出现，应优先检查对应商家归属、筛选条件和页面 API 响应，而不是增加固定等待时间。

## 7. 范围边界

- 当前支付与退款均为项目既有的模拟实现；用户退款申请会直接进入成功状态，不新增审批状态。
- AI 测试固定关闭外部模型，验证本地确定性降级回复和转人工路径，不需要 AI key。
- Flutter 真机或 `integration_test` 属于 T04，不包含在本测试工程。
- 本轮不修改 GitHub Actions；后续 CI 接入只需复用本说明中的安装和测试命令。
