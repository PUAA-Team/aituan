# UC04-UC05 用例三张图文档

本文档依据 `docs/stage-new-1/软工小学期.md` 和 `docs/stage-new-1/详细设计说明书-小学期修订版.md` 中的分工要求，为 UC04 和 UC05 分别补充需求层、概要层、详细层各一张 Markdown Mermaid 图。按照小学期要求，清单中的每个业务场景只绘制 1 张顺序图、状态图或活动图，图型限定为上述三类。

## 1. UC04 用户完成外卖点单、优惠结算和模拟支付，并查看订单详情

### 1.1 UC04 需求说明书系统级活动图

```mermaid
flowchart TD
    start((开始))
    enter[用户进入外卖商家详情]
    choose[选择餐品并维护购物车]
    checkout[进入确认订单]
    address{是否存在可配送地址}
    addAddress[新增或切换收货地址]
    coupon[选择可用优惠券]
    preview[系统试算商品金额、配送费和优惠抵扣]
    valid{是否满足起送价、库存、配送范围和优惠规则}
    revise[提示原因并返回调整]
    submit[用户提交外卖订单]
    pay[用户完成模拟支付]
    paid{支付是否成功}
    pending[保留待支付订单]
    detail[查看订单详情]
    finish((结束))

    start --> enter --> choose --> checkout --> address
    address -- 否 --> addAddress --> checkout
    address -- 是 --> coupon --> preview --> valid
    valid -- 否 --> revise --> choose
    valid -- 是 --> submit --> pay --> paid
    paid -- 否 --> pending --> detail
    paid -- 是 --> detail --> finish
```

### 1.2 UC04 概要设计组件级顺序图

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户
    participant App as 用户端APP
    participant Trade as 交易与履约组件
    participant Catalog as 商家与商品组件
    participant Coupon as 会员优惠券组件
    participant Message as 消息组件
    participant DB as MySQL数据库

    User->>App: 进入外卖商家详情
    loop 调整购物车
        User->>App: 选择商品或修改数量
    end
    User->>App: 进入结算
    App->>Trade: 请求订单试算
    Trade->>Catalog: 校验商家营业、商品在售、库存和履约规则
    Catalog-->>Trade: 返回商品快照和配送规则
    opt 用户选择优惠券
        Trade->>Coupon: 校验用户优惠券可用性
        Coupon-->>Trade: 返回优惠抵扣结果
    end
    alt 试算校验通过
        Trade-->>App: 返回试算金额
        User->>App: 确认并提交订单
        App->>Trade: 创建外卖订单
        Trade->>DB: 保存订单、明细和初始状态日志
        Trade-->>App: 返回待支付订单
        User->>App: 发起模拟支付
        App->>Trade: 提交支付确认
        alt 支付成功
            Trade->>Coupon: 确认使用优惠券
            Trade->>DB: 更新支付记录和订单状态
            Trade->>Message: 生成支付成功和待接单消息
            Message->>DB: 保存站内消息
            Trade-->>App: 返回订单详情
        else 支付失败
            Trade-->>App: 返回支付失败，订单保持待支付
        end
        App-->>User: 展示订单详情或支付失败提示
    else 试算校验失败
        Trade-->>App: 返回库存、起送价或配送范围错误
        App-->>User: 展示不可提交原因
    end
```

### 1.3 UC04 详细设计对象级顺序图

```mermaid
sequenceDiagram
    autonumber
    actor User as 用户
    participant MerchantPage as TakeawayMerchantPage
    participant CartSheet as TakeawayCartSheet
    participant CheckoutPage as CheckoutPage
    participant OrderDetail as TakeawayOrderDetailPage
    participant TradeController as TradeController
    participant TradeService as TradeService
    participant CouponService as CouponService
    participant TradeRepository as TradeRepository
    participant MessagePublisher as StationMessagePublisher

    User->>MerchantPage: 选择外卖商家
    loop 调整购物车
        User->>MerchantPage: 选择商品或修改数量
        MerchantPage->>CartSheet: 同步购物车内容
    end
    User->>CheckoutPage: 进入结算页
    CheckoutPage->>TradeController: POST /api/app/trade/checkout/preview
    TradeController->>TradeService: previewCheckout(request, currentUser)
    TradeService->>TradeRepository: 查询商品、门店、履约规则、购物车
    TradeRepository-->>TradeService: 返回商品快照和配送规则
    opt 用户选择优惠券
        TradeService->>CouponService: 校验可用优惠券并计算抵扣
        CouponService-->>TradeService: 返回抵扣结果或不可用原因
    end
    alt 试算校验通过
        TradeService-->>TradeController: 返回试算金额、配送费、优惠信息
        TradeController-->>CheckoutPage: 展示确认订单结果
        User->>CheckoutPage: 提交订单
        CheckoutPage->>TradeController: POST /api/app/trade/orders
        TradeController->>TradeService: createTakeawayOrder(request, currentUser)
        TradeService->>CouponService: 重新校验并锁定优惠券
        TradeService->>TradeRepository: 保存订单、明细、支付记录、状态日志
        TradeRepository-->>TradeService: 返回订单编号
        TradeService-->>TradeController: 返回待支付订单
        TradeController-->>CheckoutPage: 返回 orderId

        User->>CheckoutPage: 点击模拟支付
        CheckoutPage->>TradeController: POST /api/app/trade/orders/{orderId}/pay
        TradeController->>TradeService: payOrder(orderId, currentUser)
        TradeService->>TradeRepository: 校验订单归属和待支付状态
        alt 支付成功
            TradeService->>CouponService: 标记优惠券已使用
            TradeService->>TradeRepository: 更新支付成功、订单进入待商家接单
            TradeService->>MessagePublisher: 发布支付成功/待接单消息
            TradeService-->>TradeController: 返回支付结果和展示状态
            TradeController-->>CheckoutPage: 支付成功
        else 支付失败或重复支付
            TradeService-->>TradeController: 返回失败原因或幂等支付结果
            TradeController-->>CheckoutPage: 展示支付结果
        end
        CheckoutPage->>OrderDetail: 跳转订单详情
        OrderDetail->>TradeController: GET /api/app/trade/orders/{orderId}
        TradeController->>TradeService: getOrderDetail(orderId, currentUser)
        TradeService->>TradeRepository: 查询订单详情、明细、支付和状态日志
        TradeRepository-->>TradeService: 返回订单聚合数据
        TradeService-->>OrderDetail: 展示订单详情
    else 试算校验失败
        TradeService-->>TradeController: 返回库存、起送价或配送范围错误
        TradeController-->>CheckoutPage: 展示不可提交原因
    end
```

## 2. UC05 商家处理外卖订单并推进配送履约，用户接收订单状态消息

### 2.1 UC05 需求说明书系统级状态图

```mermaid
stateDiagram-v2
    [*] --> 待商家接单: 用户完成模拟支付
    待商家接单 --> 备餐中: 商家接单
    待商家接单 --> 退款处理中: 商家拒单
    备餐中 --> 待配送: 商家完成备餐
    待配送 --> 配送中: 开始配送
    配送中 --> 已送达: 配送完成
    已送达 --> 已完成: 用户确认或系统确认
    配送中 --> 履约异常: 配送超时或异常
    备餐中 --> 履约异常: 备餐异常
    履约异常 --> 配送中: 异常解除
    履约异常 --> 退款处理中: 无法继续履约
    退款处理中 --> 已退款: 退款完成
    已完成 --> [*]
    已退款 --> [*]
```

### 2.2 UC05 概要设计组件级顺序图

```mermaid
sequenceDiagram
    autonumber
    actor Merchant as 商家
    participant MerchantWeb as 商家端Web
    participant Trade as 交易与履约组件
    participant Delivery as 配送模拟组件
    participant Message as 消息组件
    participant UserApp as 用户端APP
    participant DB as MySQL数据库
    actor User as 用户

    Merchant->>MerchantWeb: 查询待处理外卖订单
    MerchantWeb->>Trade: 获取商家订单列表
    Trade->>DB: 查询订单和支付状态
    DB-->>Trade: 返回待接单订单
    Trade-->>MerchantWeb: 返回订单列表
    Merchant->>MerchantWeb: 处理订单
    alt 商家接单
        MerchantWeb->>Trade: 提交接单状态
        Trade->>DB: 校验归属并写入订单状态日志
        Trade->>Message: 发布接单消息
        Message->>DB: 保存用户站内消息
        loop 推进履约状态
            Merchant->>MerchantWeb: 推进备餐、出餐或配送
            MerchantWeb->>Trade: 提交状态变更
            Trade->>Delivery: 创建或推进配送任务
            Delivery->>DB: 写入配送时间线
            Delivery-->>Trade: 返回配送状态
            Trade->>Message: 发布配送状态消息
        end
        alt 配送正常完成
            Trade->>DB: 更新订单为已送达或已完成
        else 配送异常
            Trade->>DB: 标记履约异常
            Trade->>Message: 发布异常提醒
        end
    else 商家拒单
        MerchantWeb->>Trade: 提交拒单原因
        Trade->>DB: 订单进入取消或退款流程
        Trade->>Message: 发布拒单消息
    end
    opt 用户查看消息和配送进度
        User->>UserApp: 查看订单详情或消息中心
        UserApp->>Trade: 查询订单和配送时间线
        Trade->>DB: 读取订单、配送和消息关联数据
        Trade-->>UserApp: 返回最新履约状态
        UserApp-->>User: 展示订单状态消息
    end
```

### 2.3 UC05 详细设计对象级状态图

```mermaid
stateDiagram-v2
    [*] --> 待支付: 用户提交外卖订单
    待支付 --> 待商家接单: 模拟支付成功
    待支付 --> 已取消: 用户取消或支付超时

    待商家接单 --> 备餐中: 商家接单
    待商家接单 --> 退款中: 商家拒单或用户申请退款

    备餐中 --> 待配送: 商家标记出餐
    备餐中 --> 异常: 商家标记备餐异常

    待配送 --> 配送中: 配送模拟开始或商家推进配送
    配送中 --> 已送达: 配送完成
    配送中 --> 异常: 配送异常

    已送达 --> 已完成: 系统确认完成或用户确认收货
    已完成 --> [*]

    退款中 --> 已退款: 退款处理完成
    已退款 --> [*]
    已取消 --> [*]

    异常 --> 配送中: 异常解除后继续配送
    异常 --> 退款中: 无法履约

    note right of 待商家接单
        每次订单状态变化由 TradeService 校验并写入 order_status_log
    end note

    note right of 配送中
        配送时间线写入 delivery_timeline
        用户消息由 StationMessagePublisher 生成
    end note
```
