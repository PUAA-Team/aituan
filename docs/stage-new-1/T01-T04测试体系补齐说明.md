# T01-T04 测试体系补齐说明

## 1. 背景

本次从远端 `origin/first` 分支中只摘取与课程测试要求相关的有效内容，补齐 T01-T04 的最小测试闭环。由于 `origin/first` 是独立快照分支，包含大量无关删除和部署回退，本次没有直接合并该分支，而是在最新 `main` 上手工搬运测试相关改动。

| 编号 | 类型 | 课程检查重点 | 本次补齐内容 |
| --- | --- | --- | --- |
| T01 | 单元测试 | 关键类、方法、业务规则、异常分支，覆盖率报告和阈值 | 后端 JaCoCo、Web Vitest coverage、Flutter coverage |
| T02 | 集成 / API 测试 | 模块调用、数据库访问、外部接口 | MySQL 8 CI 迁移验证、LskyPro 图床 mock contract |
| T03 | Web 页面测试 | 商家端 / 后台端页面交互 | 商家端、后台端登录页组件测试 |
| T04 | Flutter 端到端 | APP 页面完整流程 | `integration_test` 页面流转测试 |

## 3. T02 集成 / API 测试补齐

### 3.1 MySQL 8 迁移验证

新增：

```text
services/backend/src/main/resources/application-mysql-ci.yml
services/backend/src/test/java/com/aituan/MysqlMigrationSmokeTest.java
```

`MysqlMigrationSmokeTest` 使用 `mysql-ci` profile，并通过环境变量控制是否启用：

```text
AITUAN_MYSQL_CI_ENABLED=true
```

验证内容：

1. 当前数据库产品名包含 `MySQL`。
2. Flyway 迁移记录存在并成功。
3. `demo_user`、`demo_merchant`、`demo_admin` 三类演示账号 seed 数据存在。

本地普通测试默认不启用该用例，避免无 MySQL 环境时误连真实数据库；GitHub Actions 中通过 MySQL service container 验证。

### 3.2 LskyPro 外部接口 mock contract

新增：

```text
services/backend/src/test/java/com/aituan/common/file/LskyProImageStorageClientContractTest.java
```

该测试使用 JDK 自带 `HttpServer` 模拟 LskyPro 图床接口，验证：

- 请求方法为 `POST`；
- 请求路径为 `/api/v1/upload`；
- 请求头包含 `Authorization: Bearer test-token`；
- 请求体为 `multipart/form-data` 且包含 boundary；
- 表单包含 `file`、`strategy_id`、`album_id`、`permission`；
- 能解析 mock 响应中的 `data.key` 和 `data.links.url`。

## 6. CI 集成

修改：

```text
.github/workflows/ci.yml
```

新增 / 调整：

- 后端执行 `mvn verify`，由 JaCoCo 插件生成报告并检查阈值。
- 后端 job 增加 MySQL 8.4 service container。
- CI 中显式启用 `MysqlMigrationSmokeTest` 验证真实 MySQL 迁移。
- Web merchant/admin 执行 `npm run test:coverage`，并保留测试报告产物。
- Flutter 执行 `flutter test --coverage`。
- 使用 Android emulator 执行 `flutter test integration_test -d emulator-5554`。
- 保留现有 UC01-UC13 E2E job、K8s、部署配置和文档，不接受 `origin/first` 中的无关删除。

## 7. 风险与后续建议

1. Web coverage 阈值当前较低，是为了在已有页面测试较少的情况下先形成稳定门禁，后续应按页面逐步补测并上调阈值。
2. npm 安装依赖时提示存在 high severity vulnerabilities，本次未执行 `npm audit fix`，避免自动升级依赖造成额外风险。
3. MySQL 8 smoke test 主要由 GitHub Actions service container 验证；本机无 Docker Compose 环境时不强制执行。
4. Flutter integration test 需要 Android 真机或模拟器，本地无设备时可先通过 CI emulator 验证。
