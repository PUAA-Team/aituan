# 爱团本地生活服务综合平台测试报告

## 1. 报告概述

### 1.1 报告目的

本报告用于说明“爱团本地生活服务综合平台”的测试范围、测试方法、自动化测试资产、UC01-UC13 测试用例、测试执行结果与遗留风险。报告重点覆盖单元测试、集成 / API 测试、端到端测试三个层次，说明系统是否满足本阶段课程项目的功能正确性、接口稳定性、跨端业务闭环和自动化测试覆盖要求。

本报告不记录逐日测试日志，只保留验收和答辩需要的测试用例、测试结果、覆盖关系和质量结论。

### 1.2 项目背景

爱团是一个面向城市居民的本地生活服务综合平台，对标美团、饿了么、大众点评等真实系统，覆盖外卖订餐、到店团购、休闲娱乐、生活服务、评价、客服、投诉、会员优惠、商家经营管理和平台治理等功能。

项目采用三端一后端架构：

| 端 / 服务 | 技术栈 | 主要职责 |
| --- | --- | --- |
| 用户端 | Flutter APP / Flutter Web | 用户注册登录、首页发现、搜索、下单、支付模拟、订单、会员、优惠券、评价、客服、投诉。 |
| 商家端 | Vue 3 + TypeScript | 商家登录、门店资料、商品服务目录、订单履约、券码核销、预约确认、评价回复、客服处理。 |
| 后台端 | Vue 3 + TypeScript | 管理员登录、商户治理、商品治理、订单治理、优惠券模板、评价审核、投诉工单、平台客服、审计。 |
| 后端服务 | Spring Boot + MySQL / H2 + Flyway | 认证鉴权、业务 API、交易状态机、会员优惠、客服投诉、文件上传、消息、数据库迁移。 |
| 自动化与部署 | GitHub Actions、Docker Compose、Kubernetes 文件、Playwright、Vitest、Flutter test、JUnit | 自动化测试、构建、部署、健康检查和报告产物。 |

### 2.3 测试目标

1. 验证 UC01-UC13 业务用例均有可执行自动化测试覆盖。
2. 验证用户端、商家端、后台端和后端之间的核心闭环正确。
3. 验证关键业务状态机正确，包括订单支付、履约、券码、预约、退款、评价治理、投诉、客服和会员成长值。
4. 验证接口响应、权限边界、数据库迁移、前端接口封装和数据模型解析稳定。
5. 验证自动化测试可作为 CI 门禁，测试失败时阻断后续构建或部署。

### 3.4 模型与测试层级映射

| 设计 / 需求材料 | 对应测试层级 | 当前落实方式 |
| --- | --- | --- |
| 需求规格说明书、用例描述、系统顺序图 | 系统测试 / E2E | Playwright 按 UC01-UC13 覆盖基本流程和扩展流程，验证用户、商家、后台端完整闭环。 |
| 概要设计说明书、组件协作关系 | 集成 / API 测试 | MockMvc 验证 Controller、Security、Service、Repository 和数据库迁移协作，重点覆盖交易、券码、预约、投诉、发现、目录维护等 API。 |
| 详细设计、对象级顺序图、系统操作 | 单元 / Service 测试 | JUnit 直接测试 Service 中的系统操作和业务规则，例如下单金额计算、起送价校验、退款状态变化、券码重复核销、投诉状态流转、会员成长值增长。 |

该映射与老师“写代码是一层层剥开，测试是一层层收起来”的口径一致：前端 GUI / API 负责收起用例级流程，后端 Service 单测负责对照对象级顺序图中的系统操作和状态规则。

### 3.5 通过标准

| 类型 | 通过标准 |
| --- | --- |
| 单元测试 | 断言全部通过，核心业务规则和异常分支符合预期。 |
| 集成 / API 测试 | HTTP 状态码、业务 code、响应结构、权限边界、数据库状态正确。 |
| 端到端测试 | UC01-UC13 每条业务流执行成功，页面断言和接口回查均符合预期。 |
| CI 测试 | 任一自动化测试失败时 workflow 失败并停止后续流程。 |
| 数据库迁移 | Flyway 可从空库执行，seed 数据可重复加载，不依赖手工清库。 |

## 5. UC01-UC13 端到端测试用例

### 5.1 端到端测试总体说明

端到端测试工程位于：

```text
tests/e2e
```

技术栈为 Playwright + TypeScript。测试通过真实 HTTP API 和真实前端页面完成业务闭环验证：

- 用户端：Flutter Web 页面 + 后端 API；
