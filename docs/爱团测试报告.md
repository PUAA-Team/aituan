## 1 引言

### 1.1 目的

本测试报告用于记录“爱团本地生活服务综合平台”的测试计划、测试设计、测试用例、测试过程、测试日志与测试总结。通过系统化测试，验证项目是否满足需求规格说明书、概要设计说明书、详细设计说明书以及各阶段交付文档中的功能需求、接口需求、安全需求、部署需求与质量要求。

本报告重点覆盖以下目标：

1. 验证用户端、商家端、后台端和后端服务之间的核心业务闭环是否可用。
2. 验证八大本地生活服务模块的浏览、下单、履约、评价、售后等关键路径是否符合设计。
3. 验证后端 API、权限边界、数据库迁移、文件上传、优惠券、投诉、交易等高风险功能是否稳定。
4. 验证 Flutter 用户端、Vue 商家端、Vue 后台端的前端逻辑、接口封装、构建流程和页面渲染是否可用。
5. 验证 CI/CD、Docker Compose 部署、HTTPS 访问、APK 打包和服务器健康检查等交付能力是否满足课程项目验收要求。

### 1.2 背景

爱团是一个面向城市居民的本地生活服务综合平台，对标美团、饿了么、大众点评等真实系统，覆盖外卖、团购、酒店、休闲娱乐、电影演出、丽人医美、景点门票、洗脚按摩等八大服务模块。

项目采用三端一后端架构：

- 用户端：Flutter APP / Flutter Web；
- 商家端：Vue 3 + TypeScript Web 控制台；
- 后台端：Vue 3 + TypeScript 平台管理后台；
- 后端：Spring Boot + MySQL + Flyway；
- 部署：Nginx + Docker Compose + GitHub Actions + GHCR 镜像；
- 增强能力：AI 助手、会员成长值、优惠券、评价客服投诉、平台治理与审计日志。

为保证系统最终展示和验收质量，需要对项目进行功能测试、接口测试、集成测试、安全边界测试、构建测试、部署测试和回归测试。

### 1.3 范围

本报告覆盖主要测试活动。测试范围包括：

1. 用户端 APP 功能测试：登录注册、首页、八大模块、搜索、商家详情、下单、订单详情、会员、优惠券、消息、收藏、评价、客服、投诉、AI 助手等。
2. 商家端 Web 功能测试：登录、经营总览、门店资料、商品服务管理、订单履约、券码核销、评价管理、客服会话等。
3. 后台端 Web 功能测试：登录、平台总览、商家治理、商品治理、订单治理、会员与优惠券模板、评价审核、投诉工单、平台客服、审计日志、系统配置等。
4. 后端服务测试：认证、JWT、权限边界、订单交易、优惠券、会员成长值、投诉、文件上传、评价客服、数据库迁移和 seed 数据。
5. 前端自动化测试：Flutter 单元测试 / Widget 测试、Vue API 层测试、TypeScript 构建校验。
6. 部署与交付测试：Docker Compose、CI/CD workflow、HTTPS 证书、Nginx 路由、健康检查、APK 打包。
7. 回归测试：成员 E 静态回归脚本、Stage7 UI 重构回归、登录验证码和定位调试反馈关闭验证。

不在本轮测试范围内的内容：

- 真实微信 / 支付宝支付；
- 真实骑手端与实时地图轨迹；
- 酒店真实房态、电影选座、复杂技师排班；
- 大规模压力测试和覆盖率阈值门禁；
- 生产级 AI 调用日志分析和完整 Agent 治理平台。

### 2.3 测试方法

测试采用以下方法：

1. **黑盒功能测试**：以用户视角验证输入、操作和输出是否符合需求。
2. **接口集成测试**：使用 MockMvc 调用后端真实 Controller，验证 HTTP 状态码、统一响应结构、参数校验和业务数据。
3. **服务层集成测试**：直接测试 Service 和 Repository，验证状态机、数据库写入和幂等逻辑。
4. **权限边界测试**：用真实 JWT 测试 USER、MERCHANT、ADMIN 访问边界。
5. **前端单元测试**：用 Flutter test 和 Vitest 测试纯逻辑、模型解析、Repository 请求路径和 API 封装。
6. **Widget / 页面烟测**：验证启动页、Web 不支持页、底部操作栏和主要页面渲染。
7. **静态回归测试**：用 Bash + grep 检查跨端关键入口、文案和文件结构是否被误删。
8. **构建测试**：执行 Maven、npm、Flutter 构建，验证产物可生成。
9. **部署测试**：启动 Docker Compose 或 CI/CD 镜像部署，验证 Nginx、后端健康检查和页面入口。
10. **回归测试**：修复缺陷后重新执行对应测试用例，确认问题关闭。

### 2.4 测试通过标准

测试通过标准如下：

1. P0 主链路功能可用：登录、浏览、下单、支付模拟、履约、订单详情、评价、客服 / 投诉、后台治理。
2. 自动化测试全部通过：后端 Maven test、Flutter analyze/test、Web npm test/build、静态回归脚本。
3. API 响应符合统一结构，关键错误能返回合理业务提示。
4. 角色权限边界正确：未登录拒绝、角色串访问拒绝、公开接口可访问。
5. 数据库迁移可从空库执行，seed 数据幂等可重复加载。
6. 前端构建产物可被 Nginx 正确访问，刷新深层路由不 404。
7. Docker Compose 或 CI/CD 部署后 `/actuator/health` 返回 UP。
8. HTTPS 配置后，HTTP 能跳转到 HTTPS，HTTPS 页面和 API 均可访问。
9. 修复后的缺陷经回归测试确认不复现。

### 2.5 测试流程

1. 阅读需求规格、概要设计、详细设计和阶段文档。
2. 制定测试计划和功能清单。
3. 准备测试数据、演示账号和测试环境。
4. 执行后端服务层测试和 API 集成测试。
5. 执行用户端 Flutter 单元测试、Widget 测试和页面烟测。
6. 执行商家端 / 后台端 Web API 层测试和构建测试。
7. 执行三端联调和人工业务闭环测试。
8. 执行部署、CI/CD、HTTPS、APK 打包测试。
9. 记录缺陷并分配修复。
10. 修复后回归测试。
11. 汇总测试结论并输出测试报告。

### 7.2 主要缺陷与修复情况

| 缺陷 | 影响 | 修复情况 |
| --- | --- | --- |
| Web 测试中 API base URL 写死 localhost | CI 环境使用不同 origin 时失败 | 改为读取 `import.meta.env.VITE_API_BASE_URL`，已回归通过。 |
| npm ci 锁文件与 Vite 依赖不一致 | Web CI 安装失败 | 固定 Vite 版本并同步 lockfile，已回归通过。 |
| 文件上传测试读取真实上传策略 | 测试环境可能走外部图床 | 测试中显式指定 local 策略，已通过。 |
| Flutter 起送金额 epsilon 边界受浮点误差影响 | 金额边界测试不稳定 | 改为按 epsilon 公式构造边界值，已通过。 |
| 静态回归脚本迁移文件名过期 | CI 静态回归失败 | 修正脚本中的迁移版本号，已通过。 |
| Nginx 初始配置只有 HTTP | 公开域名无 HTTPS | 接入 Let's Encrypt，配置 443 和 HTTP 跳转，已验证。 |
| 用户端构建开启定位调试反馈 | 公开演示可能显示测试错误信息 | 移除 `LOCATION_DEBUG_ERRORS=true`，已关闭。 |
| 邮箱验证码可直接返回到前端 | 公开演示可能泄露测试验证码 | 前端不再显示 code，后端默认关闭 debug 返回，已验证。 |
