# 爱团部署文档

> 本文面向接手部署本项目的其他使用者，说明如何准备配置、构建产物、部署服务、验证运行状态，以及如何接入 CI/CD 自动化部署。  
> 文中所有路径、域名、账号和密钥均使用占位符，不包含任何个人环境、真实服务器地址、真实密钥或固定绝对目录。部署时请按自己的服务器情况替换。

## 1. 文档范围

本文覆盖两种部署方式：

1. **Docker Compose 部署**：推荐方式。通过 Docker Compose 统一运行 MySQL、后端和 Nginx。适合课程验收、演示服务器、小型生产环境。
2. **常规配置安装**：不使用 Docker 运行后端和 Nginx，手动安装 Java、MySQL、Nginx，并使用 systemd 或等价方式托管 Spring Boot 后端。适合已有服务器运维体系或不能使用 Docker 的环境。

本文还补充：

- `.config` 配置方法；
- `deploy/.env` 配置方法；
- 前端和后端构建方法；
- 健康检查和上线验证；
- 更新、回滚和备份建议；
- GitHub Actions / CI/CD 自动化部署流程。

## 2. 系统组成

爱团系统采用前后端分离架构，主要交付内容如下：

| 组成 | 技术 | 部署形式 |
| --- | --- | --- |
| 用户端 APP | Flutter | Android APK，可单独分发，也可放入下载目录 |
| 用户端 Web | Flutter Web | 静态文件，由 Nginx 托管在 `/web/` 路径 |
| 商家端 Web | Vue 3 + Vite | 静态文件，由 Nginx 托管在 `/merchant/` 路径 |
| 后台端 Web | Vue 3 + Vite | 静态文件，由 Nginx 托管在 `/admin/` 路径 |
| 后端服务 | Spring Boot + Java 17 | JAR 运行或 Docker 容器运行 |
| 数据库 | MySQL 8 | 持久化存储业务数据 |
| 反向代理 | Nginx | 静态资源托管、API 反向代理、健康检查入口 |
| 配置文件 | `.config`、`deploy/.env` | 保存运行环境、数据库、密钥和外部服务配置 |

推荐公开访问路径：

| 路径 | 用途 |
| --- | --- |
| `/` | 项目入口页或下载说明页 |
| `/web/` | 用户端 Web |
| `/merchant/` | 商家端 Web |
| `/admin/` | 平台后台 Web |
| `/api/...` | 后端 API |
| `/actuator/health` | 后端健康检查 |
| `/downloads/...` | APK 或其他下载文件 |

## 3. 部署前准备

### 3.1 基础环境要求

#### Docker Compose 部署

服务器建议准备：

- Linux 服务器或可运行 Docker 的环境；
- Docker Engine；
- Docker Compose Plugin；
- 可访问外网拉取基础镜像或业务镜像；
- 至少开放 HTTP / HTTPS 对外访问端口；
- 可选：域名和 HTTPS 证书。

#### 常规配置安装

服务器建议准备：

- Java 17；
- MySQL 8；
- Nginx；
- 可选：systemd 或其他进程守护工具；
- 可选：Maven、Node.js、Flutter。如果服务器只负责运行，不负责构建，可以不安装这些构建工具。

#### 构建机建议准备

如果不在服务器上构建，构建机需要：

- Java 17 + Maven；
- Node.js + npm；
- Flutter；
- Git；
- 可选：Docker Buildx，用于构建镜像。

### 3.2 仓库目录说明

项目主要目录：

```text
<REPO_ROOT>/
├─ apps/
│  ├─ user_app/          # Flutter 用户端
│  ├─ merchant_web/      # 商家端 Web
│  └─ admin_web/         # 后台端 Web
├─ services/backend/     # Spring Boot 后端
├─ database/
│  ├─ migrations/        # Flyway 数据库迁移
│  └─ seeds/             # 演示数据 seed
├─ deploy/               # Docker、Nginx、部署产物目录
├─ scripts/              # 构建脚本
└─ docs/                 # 项目文档
```

部署时建议在服务器上规划以下逻辑目录，实际路径由使用者自行决定：

```text
<APP_DIR>                 # 项目部署目录，存放 deploy 文件、静态产物和配置
<DATA_DIR>                # 数据目录，存放 MySQL 数据和上传文件
<BACKUP_DIR>              # 备份目录，存放每次部署前的备份
<CONFIG_FILE>             # 后端业务配置文件，对应项目模板 .config.example
```

> 不建议把真实密钥、数据库密码、第三方 Token 写入 Git 仓库或公开文档。

## 4. `.config` 配置方法

`.config` 是后端业务配置文件，用于保存 JWT、AI、邮箱、图片上传、地图等配置。项目根目录提供模板：

```text
.config.example
```

部署时请复制模板为实际配置文件：

```bash
cp .config.example .config
```

也可以将 `.config` 放在服务器上的其他位置，并通过环境变量 `AITUAN_CONFIG_FILE` 指定：

```bash
export AITUAN_CONFIG_FILE=<CONFIG_FILE>
```

后端默认会尝试读取：

```text
${AITUAN_CONFIG_FILE}
.config
../../.config
```

Docker Compose 部署中通常将宿主机 `.config` 挂载到容器内：

```yaml
AITUAN_CONFIG_FILE: /app/.config
```

### 4.1 JWT 配置

必须设置强随机 JWT secret：

```properties
aituan.security.jwt-secret=<LONG_RANDOM_SECRET>
```

生成示例：

```bash
openssl rand -base64 48
```

注意：

- 不要使用模板中的默认值；
- 更换 JWT secret 会让已有登录 Token 失效；
- 生产环境不要把 JWT secret 写入仓库。

### 4.2 AI 助手配置

AI 助手配置项：

```properties
aituan.ai.enabled=false
aituan.ai.api-url=<AI_API_BASE_URL>
aituan.ai.api-key=<AI_API_KEY>
aituan.ai.model=<MODEL_NAME>
aituan.ai.timeout-seconds=20
aituan.ai.max-tokens=800
aituan.ai.temperature=0.25
```

说明：

| 配置 | 说明 |
| --- | --- |
| `aituan.ai.enabled` | 是否启用真实 AI 模型调用。为 `false` 时走本地降级回复。 |
| `aituan.ai.api-url` | AI 服务基础地址。后端会拼接或识别 `/v1/chat/completions`。 |
| `aituan.ai.api-key` | AI 服务密钥。不得提交到 Git。 |
| `aituan.ai.model` | 模型名称。 |
| `aituan.ai.timeout-seconds` | 请求超时时间。 |
| `aituan.ai.max-tokens` | 单次回复最大 token 数。 |
| `aituan.ai.temperature` | 生成随机性参数。 |

AI 降级策略：

- `enabled=false`；
- `api-key` 为空；
- 外部模型接口超时；
- 模型返回为空；

以上情况不会阻断核心业务，后端会使用本地规则和业务 Skill 查询结果生成回复。

### 4.3 邮箱配置

如果需要邮件验证码，配置 SMTP：

```properties
aituan.mail.enabled=true
aituan.mail.debug-return-code=false
spring.mail.host=<SMTP_HOST>
spring.mail.port=<SMTP_PORT>
spring.mail.username=<SMTP_USERNAME>
spring.mail.password=<SMTP_PASSWORD_OR_AUTH_CODE>
spring.mail.properties.mail.smtp.ssl.enable=true
spring.mail.properties.mail.smtp.starttls.enable=false
aituan.mail.from=<MAIL_FROM>
aituan.mail.from-name=爱团
```

开发或演示环境可关闭真实邮件发送：

```properties
aituan.mail.enabled=false
aituan.mail.debug-return-code=true
```

生产或公开演示环境不建议开启 `debug-return-code=true`。

### 4.4 图片上传配置

本项目支持本地文件存储，也支持外部图床服务。

本地存储示例：

```properties
aituan.upload.strategy=local
```

如果使用外部图床，请配置对应地址和 Token：

```properties
aituan.upload.strategy=lskypro
aituan.upload.lskypro.api-url=<UPLOAD_API_URL>
aituan.upload.lskypro.token=<UPLOAD_TOKEN>
aituan.upload.lskypro.token-url=<UPLOAD_TOKEN_URL>
aituan.upload.lskypro.strategy-id=<STRATEGY_ID>
aituan.upload.lskypro.album-id=<ALBUM_ID>
aituan.upload.lskypro.permission=1
```

真实 Token 不得提交。

### 4.5 地图配置

默认可使用本地距离估算：

```properties
aituan.map.provider=local
```

如果需要接入地图服务：

```properties
aituan.map.provider=amap
aituan.map.amap.web-api-key=<MAP_WEB_API_KEY>
aituan.map.amap.geocode-url=<GEOCODE_URL>
aituan.map.amap.distance-url=<DISTANCE_URL>
aituan.map.amap.regeo-url=<REGEO_URL>
aituan.map.amap.route-url=<ROUTE_URL>
```

地图服务不可用时，应优先保证浏览、下单、订单等核心流程可继续运行。

### 4.6 `.config` 权限建议

- `.config` 应只允许部署用户和后端运行用户读取；
- Docker 容器内如果后端以非 root 用户运行，宿主机 `.config` 需要保证容器用户可读；
- 不要在终端、录屏、PPT 或日志中输出完整 `.config` 内容。

## 5. `deploy/.env` 配置方法

`deploy/.env` 是 Docker Compose 使用的环境变量文件。模板：

```text
deploy/.env.example
```

部署时复制为：

```bash
cp deploy/.env.example deploy/.env
```

常用配置：

```dotenv
MYSQL_DATABASE=<DB_NAME>
MYSQL_USER=<DB_USER>
MYSQL_PASSWORD=<DB_PASSWORD>
MYSQL_ROOT_PASSWORD=<DB_ROOT_PASSWORD>
AITUAN_DATA_DIR=<DATA_DIR>
AITUAN_CONFIG_HOST_FILE=<CONFIG_FILE_RELATIVE_OR_ABSOLUTE>
```

CI/CD 镜像化部署还需要：

```dotenv
AITUAN_IMAGE_REGISTRY=<IMAGE_REGISTRY>/<OWNER>/<REPO>
AITUAN_IMAGE_TAG=<IMAGE_TAG>
AITUAN_DOWNLOADS_DIR=<DOWNLOADS_DIR>
```

变量说明：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_DATABASE` | MySQL 数据库名。 |
| `MYSQL_USER` | 后端连接数据库的业务用户。 |
| `MYSQL_PASSWORD` | 业务用户密码。 |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码。 |
| `AITUAN_DATA_DIR` | MySQL 数据和上传文件的数据目录。 |
| `AITUAN_CONFIG_HOST_FILE` | 宿主机 `.config` 文件路径，供后端容器挂载。 |
| `AITUAN_IMAGE_REGISTRY` | CI/CD 推送镜像的仓库前缀。 |
| `AITUAN_IMAGE_TAG` | 当前部署镜像 tag。 |
| `AITUAN_DOWNLOADS_DIR` | Nginx 暴露的下载文件目录。 |

注意：

- `deploy/.env` 不应提交 Git；
- 每次部署前建议备份；
- 如果修改数据库密码，需要同步更新 MySQL 用户密码和 Compose 配置。

## 6. 部署方式一：Docker Compose 部署

Docker Compose 是推荐部署方式。它可以统一管理 MySQL、后端和 Nginx，降低部署复杂度。

### 6.1 Docker Compose 部署结构

项目提供两个 Compose 文件：

| 文件 | 场景 | 特点 |
| --- | --- | --- |
| `deploy/docker-compose.server.yml` | 手动构建产物部署 | 后端镜像在服务器本地由 JAR 构建，Web 静态产物通过目录挂载。 |
| `deploy/docker-compose.cicd.yml` | CI/CD 镜像化部署 | 后端和 Web 镜像从镜像仓库拉取，服务器不负责 Maven/npm/Flutter 构建。 |

建议：

- 课程演示或手动部署：可使用 `docker-compose.server.yml`；
- 自动化部署或多人协作：推荐使用 `docker-compose.cicd.yml`。

### 6.2 手动 Compose 部署流程

#### 步骤 1：准备服务器目录

在服务器创建部署目录、数据目录和备份目录。目录名由使用者自行决定，以下使用占位符：

```bash
mkdir -p <APP_DIR>
mkdir -p <DATA_DIR>/mysql <DATA_DIR>/uploads
mkdir -p <BACKUP_DIR>
```

#### 步骤 2：上传项目部署文件

服务器 `<APP_DIR>` 至少需要：

```text
deploy/docker-compose.server.yml
deploy/backend/Dockerfile
deploy/nginx/conf.d/default.conf
deploy/artifacts/backend/aituan-backend.jar
deploy/artifacts/landing/
deploy/artifacts/user-web/
deploy/artifacts/merchant-web/
deploy/artifacts/admin-web/
deploy/artifacts/downloads/
.config
deploy/.env
```

其中：

- `.config` 是真实业务配置；
- `deploy/.env` 是 Compose 环境变量；
- `deploy/artifacts/*` 是构建后的后端 JAR 和前端静态产物。

#### 步骤 3：构建部署产物

在构建机执行：

```bash
mvn -B -f services/backend/pom.xml test
mvn -B -f services/backend/pom.xml -DskipTests package
```

将后端 JAR 复制为：

```text
deploy/artifacts/backend/aituan-backend.jar
```

构建商家端：

```bash
npm ci --prefix apps/merchant_web
VITE_API_BASE_URL=<PUBLIC_ORIGIN> npm run build --prefix apps/merchant_web -- --base=/merchant/ --outDir <REPO_ROOT>/deploy/artifacts/merchant-web --emptyOutDir
```

构建后台端：

```bash
npm ci --prefix apps/admin_web
VITE_API_BASE_URL=<PUBLIC_ORIGIN> npm run build --prefix apps/admin_web -- --base=/admin/ --outDir <REPO_ROOT>/deploy/artifacts/admin-web --emptyOutDir
```

构建用户端 Web：

```bash
cd apps/user_app
flutter pub get
flutter analyze
flutter test
flutter build web --base-href /web/ --dart-define=API_BASE_URL=<PUBLIC_ORIGIN> --output <REPO_ROOT>/deploy/artifacts/user-web
```

如需同时提供 APK 下载，可构建 APK 后放入：

```text
deploy/artifacts/downloads/
```

项目也提供服务器版构建脚本，可按目标访问地址传入：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/build_all_server_artifacts.ps1 -ServerOrigin "<PUBLIC_ORIGIN>"
```

如果不需要重新打包 APK：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/build_all_server_artifacts.ps1 -ServerOrigin "<PUBLIC_ORIGIN>" -SkipApk
```

#### 步骤 4：检查 Compose 配置

在服务器 `<APP_DIR>` 下执行：

```bash
cd <APP_DIR>
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml config
```

如果命令能展开完整配置且没有报错，再启动。

#### 步骤 5：启动服务

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml up -d --build
```

说明：

- `mysql` 使用 MySQL 8 基础镜像；
- `backend` 根据 `deploy/artifacts/backend/aituan-backend.jar` 构建镜像；
- `nginx` 托管静态页面并代理 `/api/` 到后端；
- MySQL 数据和上传文件放在 `<DATA_DIR>`。

#### 步骤 6：查看服务状态

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml ps
```

查看后端日志：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml logs -f backend
```

查看 Nginx 日志：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml logs -f nginx
```

### 6.3 CI/CD 镜像化 Compose 部署流程

CI/CD 部署使用：

```text
deploy/docker-compose.cicd.yml
```

该方式不要求服务器本地构建后端或前端，而是从镜像仓库拉取：

```text
<IMAGE_REGISTRY>/backend:<IMAGE_TAG>
<IMAGE_REGISTRY>/web:<IMAGE_TAG>
```

#### 步骤 1：准备 `deploy/.env`

```dotenv
MYSQL_DATABASE=<DB_NAME>
MYSQL_USER=<DB_USER>
MYSQL_PASSWORD=<DB_PASSWORD>
MYSQL_ROOT_PASSWORD=<DB_ROOT_PASSWORD>
AITUAN_DATA_DIR=<DATA_DIR>
AITUAN_CONFIG_HOST_FILE=<CONFIG_FILE>
AITUAN_IMAGE_REGISTRY=<IMAGE_REGISTRY>/<OWNER>/<REPO>
AITUAN_IMAGE_TAG=<IMAGE_TAG>
AITUAN_DOWNLOADS_DIR=<DOWNLOADS_DIR>
```

#### 步骤 2：检查配置

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml config
```

#### 步骤 3：拉取镜像并启动

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml pull
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml up -d --remove-orphans
```

#### 步骤 4：验证

```bash
curl -fsS <PUBLIC_ORIGIN>/actuator/health
```

预期返回：

```json
{"status":"UP"}
```

### 6.4 Docker Compose 更新流程

部署更新前建议备份：

```bash
stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p <BACKUP_DIR>/$stamp
cp <APP_DIR>/.config <BACKUP_DIR>/$stamp/config.backup
cp <APP_DIR>/deploy/.env <BACKUP_DIR>/$stamp/deploy.env.backup
# 如有旧静态产物，也可打包 deploy/artifacts
```

手动 Compose 更新：

```bash
cd <APP_DIR>
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml up -d --build
```

CI/CD 镜像化更新：

```bash
cd <APP_DIR>
# 修改 deploy/.env 中的 AITUAN_IMAGE_TAG
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml pull
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml up -d --remove-orphans
```

### 6.5 Docker Compose 回滚流程

如果是手动部署产物：

1. 从备份恢复 `deploy/artifacts`、`.config` 或 `deploy/.env`；
2. 重新执行：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml up -d --build
```

如果是镜像化部署：

1. 将 `AITUAN_IMAGE_TAG` 改回旧 tag；
2. 执行：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml pull
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml up -d --remove-orphans
```

## 7. 部署方式二：常规配置安装

常规配置安装不使用 Docker 运行后端和 Nginx。该方式适合已有 Java、MySQL、Nginx 运维环境的服务器。

### 7.1 常规部署结构

建议逻辑结构：

```text
<APP_DIR>/
├─ backend/
│  └─ aituan-backend.jar
├─ web/
│  ├─ landing/
│  ├─ user-web/
│  ├─ merchant-web/
│  ├─ admin-web/
│  └─ downloads/
├─ logs/
├─ .config
└─ nginx/
   └─ aituan.conf

<DATA_DIR>/
├─ mysql/
└─ uploads/
```

实际目录可自行选择，文档和脚本中统一用占位符表达。

### 7.2 安装 MySQL 8

创建业务库和业务用户：

```sql
CREATE DATABASE <DB_NAME>
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER '<DB_USER>'@'%' IDENTIFIED BY '<DB_PASSWORD>';
GRANT ALL PRIVILEGES ON <DB_NAME>.* TO '<DB_USER>'@'%';
FLUSH PRIVILEGES;
```

安全建议：

- 不要对公网开放 MySQL 端口；
- 如果必须远程连接，应限制来源 IP；
- 使用强密码；
- 生产环境定期备份数据库。

### 7.3 配置后端数据源

常规安装时，可以通过环境变量指定数据库连接：

```bash
export SPRING_PROFILES_ACTIVE=dev
export SERVER_PORT=8080
export AITUAN_DATASOURCE_URL="jdbc:mysql://<DB_HOST>:<DB_PORT>/<DB_NAME>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false"
export AITUAN_DATASOURCE_USERNAME=<DB_USER>
export AITUAN_DATASOURCE_PASSWORD=<DB_PASSWORD>
export AITUAN_CONFIG_FILE=<CONFIG_FILE>
export AITUAN_UPLOAD_ROOT=<UPLOAD_DIR>
export AITUAN_UPLOAD_PUBLIC_PREFIX=/api/common/files
```

其中 `<CONFIG_FILE>` 指向实际 `.config` 文件。

### 7.4 构建并放置后端 JAR

在构建机执行：

```bash
mvn -B -f services/backend/pom.xml test
mvn -B -f services/backend/pom.xml -DskipTests package
```

将生成的后端 JAR 放到服务器：

```text
<APP_DIR>/backend/aituan-backend.jar
```

### 7.5 启动后端

直接启动示例：

```bash
java -jar <APP_DIR>/backend/aituan-backend.jar
```

更推荐使用 systemd 或等价进程管理工具托管。systemd 服务文件示例：

```ini
[Unit]
Description=Aituan Backend
After=network.target mysql.service

[Service]
Type=simple
WorkingDirectory=<APP_DIR>/backend
Environment=SPRING_PROFILES_ACTIVE=dev
Environment=SERVER_PORT=8080
```

### 7.7 配置 Nginx

Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name <DOMAIN_OR_IP>;

    client_max_body_size 8m;

    location = / {
        root <APP_DIR>/web/landing;
        try_files /index.html =404;
    }

    location = /web {
        return 301 /web/;
    }

    location /web/ {
        alias <APP_DIR>/web/user-web/;
        try_files $uri $uri/ /web/index.html;
    }

    location = /merchant {
        return 301 /merchant/;
    }

    location /merchant/ {
        alias <APP_DIR>/web/merchant-web/;
        try_files $uri $uri/ /merchant/index.html;
    }

    location = /admin {
        return 301 /admin/;
    }

    location /admin/ {
        alias <APP_DIR>/web/admin-web/;
        try_files $uri $uri/ /admin/index.html;
    }

    location /downloads/ {
        alias <APP_DIR>/web/downloads/;
        try_files $uri =404;
    }

    location = /actuator/health {
        proxy_pass http://127.0.0.1:8080/actuator/health;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 30s;
        proxy_send_timeout 120s;
        proxy_read_timeout 120s;
    }
}
```

检查并重载 Nginx：

```bash
nginx -t
systemctl reload nginx
```

如果启用 HTTPS，可在此基础上添加证书配置，或使用自动证书工具生成 HTTPS 配置。

## 8. CI/CD 与自动化部署

### 8.1 自动化目标

推荐自动化流程：

```text
提交 main 或手动触发 workflow
  ↓
运行后端测试、前端测试、Flutter 测试
  ↓
构建后端 JAR、Web 静态产物
  ↓
构建 backend/web Docker 镜像
  ↓
推送到镜像仓库
  ↓
SSH 到服务器
  ↓
更新 deploy/.env 中的镜像 tag
  ↓
docker compose pull && docker compose up -d
  ↓
健康检查 /actuator/health
```

### 8.2 GitHub Actions 相关文件

项目已有 workflow：

| 文件 | 用途 |
| --- | --- |
| `.github/workflows/ci.yml` | PR 或手动触发，运行测试和构建校验，不部署。 |
| `.github/workflows/deploy.yml` | main 或手动触发，构建镜像、推送镜像、可选部署服务器。 |
| `.github/workflows/android-apk.yml` | 手动触发用户端 Android APK 打包，可选上传到服务器下载目录。 |

### 8.3 CI/CD 需要的仓库变量和密钥

建议使用 GitHub Variables 保存非敏感配置：

| 名称 | 示例含义 |
| --- | --- |
| `SERVER_ORIGIN` | 公开访问地址，例如 `https://<DOMAIN>`，不包含 `/api`。 |
| `SERVER_APP_DIR` | 服务器部署目录，占位写法为 `<APP_DIR>`。 |
| `AUTO_DEPLOY_PRODUCTION` | 是否 main push 后自动部署。 |

建议使用 GitHub Secrets 保存敏感配置：

| 名称 | 含义 |
| --- | --- |
| `SERVER_HOST` | 服务器 SSH 地址。 |
| `SERVER_PORT` | SSH 端口。 |
| `SERVER_USER` | SSH 用户。 |
| `SERVER_SSH_KEY` | 部署专用 SSH 私钥。 |
| `SERVER_KNOWN_HOSTS` | 服务器 SSH host key。 |
| `GHCR_READ_TOKEN` | 如果镜像仓库为私有，服务器拉镜像需要只读 token。 |

注意：

- SSH 私钥不应复用个人主力密钥；
- 服务器部署用户应使用最小权限；
- 不要在 workflow 日志中输出密钥。

### 8.4 镜像标签策略

推荐每次构建推送两个 tag：

| tag | 说明 |
| --- | --- |
| `sha-<短提交号>` | 唯一版本，推荐部署和回滚使用。 |
| `main` | main 分支最新版本，便于快速查看。 |

服务器 `deploy/.env` 中固定当前部署版本：

```dotenv
AITUAN_IMAGE_REGISTRY=<IMAGE_REGISTRY>/<OWNER>/<REPO>
AITUAN_IMAGE_TAG=sha-abcdef1
```

回滚时改回旧 tag 后重新：

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml pull
docker compose --env-file deploy/.env -f deploy/docker-compose.cicd.yml up -d --remove-orphans
```

### 8.5 自动化部署前置条件

1. 服务器已经准备好 `<APP_DIR>`、`deploy/.env`、`.config`、`<DATA_DIR>`；
2. 服务器已经能运行 `docker compose`；
3. 服务器能从镜像仓库拉取业务镜像；
4. GitHub Secrets 已配置 SSH 私钥和 known_hosts；
5. `.config` 和 `deploy/.env` 中的真实密钥没有提交到仓库；
6. `/actuator/health` 可以被服务器本机或 Nginx 访问。

## 10. 常见问题排查

### 10.1 后端启动失败

排查：

```bash
# Docker Compose

docker compose --env-file deploy/.env -f deploy/docker-compose.server.yml logs --tail=120 backend

# 常规安装
journalctl -u <BACKEND_SERVICE_NAME> -n 120 --no-pager
```

常见原因：

- `.config` 文件不存在或容器内不可读；
- JWT secret、AI key、邮箱配置格式错误；
- 数据库连接失败；
- MySQL 未启动或账号权限不足；
- Flyway 迁移失败；
- 上传目录没有写权限。

### 10.2 `/actuator/health` 返回 502 或连接失败

排查：

- 后端是否启动；
- Nginx 是否代理到正确后端地址；
- Docker Compose 中 Nginx 是否能通过服务名访问后端；
- 常规部署中 Nginx 是否代理到正确端口；
- 防火墙是否拦截。

### 10.3 前端页面能打开但 API 请求失败

排查：

- 构建时 `API_BASE_URL` / `VITE_API_BASE_URL` 是否设置为公开访问地址；
- 是否错误地包含 `/api` 后缀；
- Nginx `/api/` 反向代理是否生效；
- 后端 CORS / 网关 / HTTPS 混合内容问题；
- 浏览器控制台网络请求地址是否正确。

### 10.4 上传图片失败

排查：

- `aituan.upload.strategy` 是否正确；
- 本地上传目录是否存在并可写；
- 外部图床 Token 是否有效；
- Nginx `client_max_body_size` 是否小于上传文件大小；
- `.config` 是否已在后端重启后生效。

### 10.5 邮件验证码失败

排查：

- `aituan.mail.enabled` 是否为 `true`；
- SMTP host、port、username、password 是否正确；
- 是否需要授权码而不是登录密码；
- SSL / STARTTLS 配置是否匹配邮件服务商要求；
- 公开演示环境是否误开 `debug-return-code=true`。

### 10.6 AI 助手没有调用真实模型

排查：

- `aituan.ai.enabled=true`；
- `aituan.ai.api-key` 非空；
- `aituan.ai.api-url` 可访问；
- `aituan.ai.model` 配置正确；
- 服务器能访问 AI 服务；
- 后端重启后配置已生效。

如果 AI 外部接口不可用，系统会自动降级，本身不代表核心业务故障。

### 10.7 Docker 镜像拉取失败

排查：

- `AITUAN_IMAGE_REGISTRY` 是否正确；
- `AITUAN_IMAGE_TAG` 是否存在；
- 镜像仓库是否公开；
- 私有镜像是否已在服务器执行 `docker login`；
- 服务器网络是否能访问镜像仓库。

## 11. 安全和运维建议

1. **真实密钥不入库**：`.config`、`deploy/.env`、SSH 私钥、Token 不提交 Git。
2. **部署前备份**：至少备份 `.config`、`deploy/.env`、数据库和旧产物。
3. **最小权限**：部署用户只应拥有部署目录、Docker 或服务重启所需权限。
4. **数据库不公网暴露**：MySQL 仅内网访问或仅本机访问。
5. **开启 HTTPS**：公开环境建议使用 HTTPS。
6. **日志脱敏**：不要在日志中打印密码、Token、JWT secret 和 AI key。
7. **健康检查**：每次部署后检查 `/actuator/health`。
8. **版本可追踪**：镜像部署使用 `sha-<短提交号>`，不要只依赖 `latest`。
9. **定期备份数据**：数据库和上传目录需要定期备份。
10. **升级前先测试**：新版本先跑 CI 和本地测试，再部署公开环境。
